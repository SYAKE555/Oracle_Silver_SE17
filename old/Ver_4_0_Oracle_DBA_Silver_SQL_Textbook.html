はじめに

この教材はSQL初学者がOracle DBA Silver試験で正答でき、かつ実務で誤更新・誤抽出を防げることを目的に設計している。

用語注釈: NULL は不明値であり0/空文字ではない。一意 は重複禁止。暗黙型変換 はOracle自動変換で、環境差異の不具合源になる。

第1章 リレーショナル・データベースの概要

1. 定義
リレーショナルDBは行と列の表でデータを表現し、キー制約で整合性を保証するデータ管理モデル。
2. 役割
顧客・受注・請求のような業務データを分離管理し、重複入力と矛盾更新を防ぐ。
3. 動作原理
主キーで行を一意識別し、外部キーで参照整合を維持。SQLは宣言的に要求を記述し、DBエンジンが実行順を最適化する。
4. 制限事項とアンチパターン
主キー未定義、外部キー未設定、NULL誤用は重大な品質劣化。自然キーを安易に主キー化すると変更に弱い。
5. 試験・実務の急所
SQL分類（DQL/DML/DDL/TCL）とキー概念は頻出。実務では最初のモデル設計が後工程工数を左右する。

図解テキスト

customers (PK: customer_id) 1 --- n orders (PK: order_id, FK: customer_id)
orders 1 --- n order_items (PK: item_id, FK: order_id)
失敗例: 顧客名を主キー化し表記ゆれで重複顧客が発生。
修正: 代理キー（NUMBER）を主キーにし、名称は別制約で管理。
SELECT table_name FROM user_tables ORDER BY table_name;

第2章 SELECT文を使用したデータ取得

1. 定義
SELECTは表から列と行を指定し結果集合を返す参照SQL。
2. 役割
画面表示、帳票出力、API応答など参照機能の基盤。
3. 動作原理
論理順序は FROM→WHERE→GROUP BY→HAVING→SELECT→ORDER BY。記述順と同一ではない。
4. 制限事項とアンチパターン
SELECT * 乱用、= NULL 比較、演算子優先順位誤りは典型障害。
5. 試験・実務の急所
処理順とNULL比較は高頻出。実務では列明示・条件明示で保守性を担保する。

処理順図

FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY
SELECT employee_id, last_name, salary
FROM employees
WHERE department_id = 50
  AND salary >= 8000
ORDER BY salary DESC;
失敗例(ORA-00904): SELECT salry FROM employees;（列名誤字）
修正: salary を指定。
失敗例: salary = NULL は常に不成立。
修正: salary IS NULL を使用。

第3章 データ制限とソート

1. 定義
ORDER BYは並び順定義、OFFSET/FETCHは取得範囲制御。
2. 役割
ページング、ランキング、バッチ抽出を再現可能にする。
3. 動作原理
ソートキー確定後に範囲切り出し。順序未定義は結果非決定。
4. 制限事項とアンチパターン
ORDER BYなし行制限、同値キーのみソートでページ重複。
5. 試験・実務の急所
NULLS FIRST/LAST と FETCH句は試験頻出。実務では第2キーに主キーを追加。
SELECT employee_id, last_name, salary
FROM employees
ORDER BY salary DESC, employee_id ASC
OFFSET 20 ROWS FETCH NEXT 10 ROWS ONLY;
失敗例: 順序キー重複でページング結果が揺れる。
修正: 複合ソートキーで一意化。

置換変数

DEFINE dept_id = 50
SELECT last_name, salary
FROM employees
WHERE department_id = &dept_id;

第5章 変換関数・NULL処理・条件式

1. 定義
型変換関数はデータ型を明示変換し、条件式はSQL内分岐を定義する。
2. 役割
入力データの型統一、NULL補完、業務区分判定を安定化する。
3. 動作原理
TO_CHAR/TO_DATE/TO_NUMBER/CASTで型整合し、NVL系やCASEで評価分岐する。
4. 制限事項とアンチパターン
暗黙変換依存、NULL等号比較、CASE戻り値型不一致は不具合要因。
5. 試験・実務の急所
型変換とNULL関数差異は頻出。実務では入力境界値テストを必須化。

変換関数

TO_DATETO_DATE(char,fmt[,nls])DATE日付化TO_DATE('2026-04-01','YYYY-MM-DD')
TO_NUMBERTO_NUMBER(char,fmt[,nls])NUMBER数値化TO_NUMBER('12,345','99,999')

CASE例

SELECT employee_id,
  CASE
    WHEN salary >= 12000 THEN 'A'
    WHEN salary >= 8000 THEN 'B'

第6章 集計データのレポート（GROUP BY / HAVING / 疑似列）

1. 定義
グループ関数は複数行を1値へ集約する関数群。GROUP BY は集約単位を定義する。
2. 役割
部門別平均、月次売上、件数集計などKPI作成の土台。
3. 動作原理
WHEREで行を絞り、GROUP BYで単位化、HAVINGで集約結果を絞る。
4. 制限事項とアンチパターン
GROUP BYにない列をSELECTするとORA-00979。WHEREとHAVINGの責務混同に注意。
5. 試験・実務の急所
COUNT(*) と COUNT(col) の差、NULL除外挙動、HAVINGの評価位置が頻出。

グループ関数一覧（主要）

関数意味NULL扱い例
COUNT(*)行数NULL含むCOUNT(*)
COUNT(col)非NULL行数NULL除外COUNT(commission_pct)
SUM(col)合計NULL除外SUM(salary)
AVG(col)平均NULL除外AVG(salary)
MAX/MIN最大/最小NULL除外MAX(hire_date)
SELECT department_id, AVG(salary) AS avg_sal
FROM employees
GROUP BY department_id
HAVING AVG(salary) >= 9000;
失敗例(ORA-00979): GROUP BY句にない列をSELECT。
修正: 集約列にするかGROUP BYへ追加。

ROWID / ROWNUM

SELECT rowid, employee_id FROM employees WHERE rownum <= 5;

第7章 複数表結合（INNER / OUTER / CROSS / NATURAL）

1. 定義
JOINは複数表の関連行を結合して1つの結果集合を作る操作。
2. 役割
顧客名と注文情報のように、分割管理データを業務表示に再構成する。
3. 動作原理
結合条件（ON/USING）で行をマッチングし、種別に応じて不一致行の扱いが変わる。
4. 制限事項とアンチパターン
条件漏れはデカルト積で件数爆発。NATURAL JOINは暗黙列依存で保守性低下。
5. 試験・実務の急所
INNERとOUTERの結果差、LEFT/RIGHT方向性、ON句位置が頻出。
INNER JOIN: 一致行のみ
LEFT JOIN : 左表全行 + 一致しない右側はNULL
RIGHT JOIN: 右表全行 + 一致しない左側はNULL
CROSS JOIN: 全組合せ（件数 = 左件数 × 右件数）
SELECT e.employee_id, d.department_name
FROM employees e
LEFT JOIN departments d
  ON e.department_id = d.department_id;
失敗例: ON句欠落で件数爆発。
修正: 参照キー同士の条件を必ず明示。

第8章 副問合せ（単一行/複数行/相関）

1. 定義
副問合せはSQL内にネストされたSELECT。
2. 役割
段階評価で「平均以上」「存在有無」などの条件を表現する。
3. 動作原理
非相関は内側先行、相関は外側行ごとに内側評価。
4. 制限事項とアンチパターン
単一行副問合せが複数行を返すとORA-01427。NOT IN + NULLで0件化。
5. 試験・実務の急所
演算子選択（=, IN, ANY, ALL, EXISTS）が最重要。
SELECT e.employee_id
FROM employees e
WHERE e.salary > (
  SELECT AVG(i.salary)
  FROM employees i
  WHERE i.department_id = e.department_id
);
失敗例(ORA-01427): 単一行比較に複数行副問合せ。
修正: IN/ANY/ALLへ変更、または副問合せを単一化。

第9章 集合演算子（UNION/UNION ALL/INTERSECT/MINUS）

1. 定義
複数SELECT結果を集合として統合・比較する演算。
2. 役割
異なる条件結果の統合、差分抽出、共通集合抽出に利用。
3. 動作原理
列数と型グループ整合を満たしたSELECT同士を演算子順で評価。
4. 制限事項とアンチパターン
列数不一致/型不整合はエラー。UNIONの重複除去はコスト増。
5. 試験・実務の急所
性能重視はUNION ALL、重複排除必要時のみUNION。
SELECT employee_id FROM employees WHERE department_id = 10
UNION ALL
SELECT employee_id FROM employees WHERE department_id = 20;
失敗例: 1本目NUMBER、2本目VARCHAR2の混在。
修正: CASTで型を統一。

第10章 DML（INSERT/UPDATE/DELETE/MERGE）とトランザクション

1. 定義
DMLは表データの追加・更新・削除を行う命令群。
2. 役割
業務状態の更新（受注確定、在庫引当、ステータス遷移）を反映する。
3. 動作原理
変更はトランザクション単位で管理され、COMMITで確定、ROLLBACKで取消。
4. 制限事項とアンチパターン
WHERE漏れ全件更新、COMMIT後取消不可、MERGEキー重複で意図外更新。
5. 試験・実務の急所
SAVEPOINT、暗黙COMMIT（DDL）との関係が頻出。

INSERT/UPDATE/DELETE

INSERT INTO departments(department_id,department_name) VALUES(290,'Ops');
UPDATE employees SET salary = salary*1.03 WHERE department_id=50;
DELETE FROM departments WHERE department_id=290;

MERGE

MERGE INTO sales_target t
USING (SELECT 10 dept_id, 1200000 amt FROM dual) s
ON (t.dept_id=s.dept_id)
WHEN MATCHED THEN UPDATE SET t.target_amt=s.amt
WHEN NOT MATCHED THEN INSERT(dept_id,target_amt) VALUES(s.dept_id,s.amt);
失敗例: WHERE漏れUPDATE。
修正: 同条件SELECTで件数確認→SAVEPOINT→更新→差分確認。

第11章 DDL（CREATE/ALTER/DROP/TRUNCATE）と制約

1. 定義
DDLは表や制約などオブジェクト構造を定義・変更する命令。
2. 役割
業務データを壊れにくくする土台を作る。
3. 動作原理
データ辞書が更新され、構造定義が即時反映される。DDLは暗黙COMMITを伴う。
4. 制限事項とアンチパターン
制約なし運用は不正データ温床。DROP/TRUNCATE混同で復旧困難。
5. 試験・実務の急所
PK/FK/UNIQUE/CHECK/NOT NULL の適用タイミングと意味が頻出。
CREATE TABLE orders(
  order_id NUMBER PRIMARY KEY,
  customer_id NUMBER NOT NULL,
  amount NUMBER(10,2) CHECK(amount >= 0)
);
ALTER TABLE orders ADD(memo VARCHAR2(200));
TRUNCATE TABLE orders;
失敗例: 既存NULLデータのある列へNOT NULL追加で失敗。
修正: 先にNULL補正してから制約追加。

第12章 ビューの管理

1. 定義
ビューはSELECT定義を名前付きで保存した仮想表。
2. 役割
共通ロジック再利用、公開列の制限、問い合わせ標準化。
3. 動作原理
参照時に定義SQLが評価される。定義更新はCREATE OR REPLACEで行う。
4. 制限事項とアンチパターン
更新不可ビューにDMLすると失敗。依存関係未管理で影響調査漏れ。
5. 試験・実務の急所
単純ビューと複雑ビューのDML可否が頻出。
CREATE OR REPLACE VIEW v_emp_sales AS
SELECT e.employee_id, e.last_name, d.department_name
FROM employees e JOIN departments d
  ON e.department_id=d.department_id;

第13章 索引・シノニム・シーケンス

1. 定義
索引は探索高速化、シノニムは別名、シーケンスは一意採番。
2. 役割
検索性能、命名抽象化、ID採番を分離して管理する。
3. 動作原理
索引はキー順構造で探索短縮。NEXTVALで採番が前進し、ROLLBACKで戻らない。
4. 制限事項とアンチパターン
索引乱立で更新遅延。シーケンス欠番を不具合と誤認しない。
5. 試験・実務の急所
CURRVAL/NEXTVAL前後関係、索引の副作用が頻出。
CREATE INDEX idx_orders_customer ON orders(customer_id);
CREATE SYNONYM ord FOR orders;
CREATE SEQUENCE orders_seq START WITH 1 INCREMENT BY 1;

1. 定義
システム権限/オブジェクト権限/ロールでアクセスを統制する。
2. 役割

4. 制限事項とアンチパターン

CREATE ROLE report_reader;
GRANT SELECT ON orders TO report_reader;
GRANT report_reader TO app_user;
REVOKE report_reader FROM app_user;

第16章 タイムゾーンと期間データ型

1. 定義
日時型は時刻情報を保持し、TZ付き型はタイムゾーンを保持する。
2. 役割
拠点間運用で時刻齟齬を防ぎ、監査時系列を一貫させる。
3. 動作原理
CURRENT_TIMESTAMPやAT TIME ZONEで表示TZを変換する。
4. 制限事項とアンチパターン
DATEのみ運用で拠点差異を吸収できない。TZ基準未統一で監査不整合。
5. 試験・実務の急所
TIMESTAMP WITH (LOCAL) TIME ZONE の違い、INTERVAL演算が頻出。
SELECT CURRENT_TIMESTAMP AS ts_local,
       CURRENT_TIMESTAMP AT TIME ZONE '+00:00' AS ts_utc,
       CURRENT_TIMESTAMP + INTERVAL '90' MINUTE AS plus_90m
FROM dual;
