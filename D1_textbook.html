リレーショナルデータベースとSQL概要
リレーショナルデータベーステーブル行列主キー

リレーショナルデータベースとは

リレーショナルデータベース（RDB）は、データをテーブル（表）の形式で管理するデータベースです。テーブルは行（レコード）と列（カラム）で構成されます。

用語説明例
テーブル（表）データを格納する2次元の表EMPLOYEES テーブル
行（レコード）テーブルの1件分のデータ従業員1人分の情報
列（カラム）データの属性（項目）EMPLOYEE_ID, LAST_NAME 等
主キー（PK）行を一意に識別する列EMPLOYEE_ID
外部キー（FK）他テーブルの主キーを参照する列DEPARTMENT_ID

SQL とは

SQL（Structured Query Language）はリレーショナルデータベースを操作するための標準言語です。以下の4種類の操作があります。

分類コマンド説明
DQL（データ照会）SELECTデータの検索・取得
DML（データ操作）INSERT, UPDATE, DELETEデータの追加・変更・削除
DDL（データ定義）CREATE, ALTER, DROPテーブル等の構造定義
TCL（トランザクション制御）COMMIT, ROLLBACK, SAVEPOINTトランザクション管理
試験のポイント： Oracle では SELECT も DML に含める場合がありますが、試験では DML = INSERT/UPDATE/DELETE として扱うことが多いです。
練習問題
問題 1 #OSLV-D1-001

以下のSELECT文の出力として正しいものはどれか。
```sql
SELECT last_name || ', ' || first_name AS full_name
FROM employees
WHERE employee_id = 100;
```
last_name='King', first_name='Steven' のとき。

  • A. King Steven
  • B. King, Steven
  • C. 'King', 'Steven'
  • D. KingSteven
解答・解説を見る

正解: B. King, Steven

正解は「King, Steven」である。Oracle SQLの連結演算子||は文字列を結合する。'King' || ', ' || 'Steven' の結果は 'King, Steven' となる。AS full_name は列の別名を定義するが出力値には影響しない。選択肢Aはカンマとスペースがない。選択肢Cはシングルクォートが余分に含まれている。選択肢Dは区切りなしの結合となっている。Oracle SQL Reference §連結演算子参照。

問題 2 #OSLV-D1-002

以下のSQL文の実行結果として正しいものはどれか。
```sql
SELECT DISTINCT department_id
FROM employees;
```
employeesテーブルに department_id が 10,10,20,20,30,NULL,NULL の7行が存在する場合。

  • A. 10, 20, 30 の3行（NULLは除外）
  • B. 10, 10, 20, 20, 30 の5行
  • C. 10, 20, 30, NULL の4行
  • D. エラーになる
解答・解説を見る

正解: C. 10, 20, 30, NULL の4行

正解は「10, 20, 30, NULL の4行」である。DISTINCTは重複行を除去するが、NULLも1つの値として扱われるため、NULLが複数あっても1行のNULLとして返される。したがって結果は 10, 20, 30, NULL の4行となる。選択肢AはNULLを除外しているため誤り。Oracle SQL Reference §SELECT文のDISTINCT句参照。

SELECT文の基本構文
SELECTFROM列別名ASDISTINCTDUAL

SELECT 文の基本

SELECT 文はデータベースからデータを取得する最も基本的な命令です。

-- 基本構文
SELECT 列名1, 列名2, ...
FROM   テーブル名;

-- 全列を取得する場合
SELECT *
FROM   EMPLOYEES;
-- 実行結果例：
-- EMPLOYEE_ID  LAST_NAME   SALARY  DEPARTMENT_ID  ...
-- -----------  ----------  ------  -------------
--         100  King         24000             90
--         101  Kochhar      17000             90
--         102  De Haan      17000             90
-- （全列・全行が返される）

-- 特定の列を取得する場合
SELECT EMPLOYEE_ID, LAST_NAME, SALARY
FROM   EMPLOYEES;
-- 実行結果例：
-- EMPLOYEE_ID  LAST_NAME   SALARY
-- -----------  ----------  ------
--         100  King         24000
--         101  Kochhar      17000
--         102  De Haan      17000

列別名（AS）

列に別名（エイリアス）を付けることができます。スペースや特殊文字を含む場合はダブルクォートで囲みます。

SELECT LAST_NAME AS 名前,
       SALARY AS 給与,
       SALARY * 12 AS "年間給与"
FROM   EMPLOYEES;
-- 実行結果例：
-- 名前        給与    年間給与
-- ----------  ------  --------
-- King         24000    288000
-- Kochhar      17000    204000
-- De Haan      17000    204000

DISTINCT で重複排除

-- 重複を排除して部署IDを取得
SELECT DISTINCT DEPARTMENT_ID
FROM   EMPLOYEES;
-- 実行結果例：
-- DEPARTMENT_ID
-- -------------
--            10
--            20
--            30
--            40
--            50
-- （重複なし、NULL があれば1行として表示）

DUAL テーブル

DUAL は Oracle が提供する特殊な1行1列のダミーテーブルです。関数の確認や計算式のテストに使います。

-- 現在日時の確認
SELECT SYSDATE FROM DUAL;
-- 実行結果例：
-- SYSDATE
-- -------------------
-- 2024-04-03 10:30:00

-- 計算式のテスト
SELECT 2 + 3 FROM DUAL;
-- 実行結果例：
-- 2+3
-- ---
--   5
試験のポイント： 列別名にダブルクォートを使うと大文字小文字が区別されます。AS は省略可能ですが、試験では AS を明示するパターンが多く出題されます。DISTINCT は SELECT の直後に1つだけ記述可能です。

問題 3 #OSLV-D1-003

NULLに関する説明として正しいものはどれか。

  • A. NULL + 100 の結果はNULLになる
  • B. NULL = NULL はTRUEになる
  • C. NULL は 0 と等しい
  • D. NULLの列をORDER BYでソートすると常に先頭になる
解答・解説を見る

正解: A. NULL + 100 の結果はNULLになる

正解は「NULL + 100 の結果はNULLになる」である。NULLは「不明な値」であり、NULLを含む算術演算の結果は常にNULLになる。NULL = NULLはTRUEではなくUNKNOWNになるため、NULLの比較にはIS NULLまたはIS NOT NULLを使う必要がある。NULLは0でも空文字でもない。ORDER BYでのNULLの順序はデフォルトでは昇順（ASC）のとき最後、降順（DESC）のとき最初になる（NULLS FIRST/NULLS LASTで制御可能）。

NULL の基礎
NULLIS NULLIS NOT NULL算術演算連結演算子

NULL とは

NULL は「値が存在しない」「不明」を表す特殊な値です。0（ゼロ）や空文字とは異なります。

NULL を含む算術演算

NULL を含む算術演算の結果は必ず NULL になります。

-- COMMISSION_PCT が NULL の場合、結果も NULL
SELECT LAST_NAME,
       SALARY * COMMISSION_PCT AS コミッション
FROM   EMPLOYEES;
-- 実行結果例：
-- LAST_NAME   コミッション
-- ----------  ------------
-- King                （NULL）
-- Abel                2100
-- Taylor              1540
-- （COMMISSION_PCT が NULL の行はコミッションも NULL になる）

IS NULL / IS NOT NULL

NULL の比較には = や != は使えません。IS NULL / IS NOT NULL を使います。

-- コミッションがない（NULL）従業員
SELECT LAST_NAME
FROM   EMPLOYEES
WHERE  COMMISSION_PCT IS NULL;
-- 実行結果例：
-- LAST_NAME
-- ----------
-- King
-- Kochhar
-- De Haan
-- （COMMISSION_PCT が NULL の行のみ返される）

-- コミッションがある（NULL でない）従業員
SELECT LAST_NAME
FROM   EMPLOYEES
WHERE  COMMISSION_PCT IS NOT NULL;
-- 実行結果例：
-- LAST_NAME
-- ----------
-- Abel
-- Taylor
-- Grant
-- （COMMISSION_PCT に値がある行のみ返される）

文字列連結演算子（||）

-- || で文字列を連結
SELECT FIRST_NAME || ' ' || LAST_NAME AS 氏名
FROM   EMPLOYEES;
-- 実行結果例：
-- 氏名
-- ---------------
-- Steven King
-- Neena Kochhar
-- Lex De Haan
試験のポイント： NULL = NULL は FALSE（NULL を比較演算子で比較できない）。NULL を含む列の ORDER BY は、デフォルトで昇順の場合 NULLS LAST、降順の場合 NULLS FIRST の動作となります。
