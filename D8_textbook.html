D8: DDL・オブジェクト管理

Oracle Database SQL (1Z0-071) 対策
テーブルやオブジェクトの作成・変更・削除など、データ定義言語（DDL）とデータベースオブジェクトの管理を学びます。
CREATE TABLE と制約
CREATE TABLEALTER TABLEDROP TABLEPRIMARY KEYFOREIGN KEYNOT NULLUNIQUECHECKDEFAULT

CREATE TABLE の基本

CREATE TABLE EMPLOYEES (
    EMPLOYEE_ID   NUMBER(6)     CONSTRAINT emp_pk PRIMARY KEY,
    FIRST_NAME    VARCHAR2(20),
    LAST_NAME     VARCHAR2(25)  CONSTRAINT emp_lname_nn NOT NULL,
    EMAIL         VARCHAR2(25)  CONSTRAINT emp_email_uk UNIQUE,
    HIRE_DATE     DATE          DEFAULT SYSDATE,
    SALARY        NUMBER(8,2)   CONSTRAINT emp_salary_ck CHECK (SALARY > 0),
    DEPARTMENT_ID NUMBER(4)     CONSTRAINT emp_dept_fk
                               REFERENCES DEPARTMENTS(DEPARTMENT_ID)
);

制約の種類

制約説明
PRIMARY KEY行を一意に識別。NOT NULL + UNIQUE の組み合わせ
FOREIGN KEY別テーブルの主キーを参照。参照整合性を保証
UNIQUE列の値を一意に保つ（NULL は複数可）
NOT NULLNULL 値を禁止する
CHECK列の値が条件を満たすことを保証
DEFAULT値が指定されない場合のデフォルト値（制約ではなく列オプション）

ALTER TABLE / DROP TABLE

-- 列の追加
ALTER TABLE EMPLOYEES ADD (NOTES VARCHAR2(100));

-- 列の変更
ALTER TABLE EMPLOYEES MODIFY (FIRST_NAME VARCHAR2(30));

-- 列の削除
ALTER TABLE EMPLOYEES DROP COLUMN NOTES;

-- テーブルの削除（データも削除）
DROP TABLE COPY_EMPLOYEES;

-- テーブルの削除（PURGE: ごみ箱に入れない）
DROP TABLE COPY_EMPLOYEES PURGE;
試験のポイント： PRIMARY KEY は1テーブルに1つだけ設定可能です。UNIQUE は複数可。FOREIGN KEY の参照先テーブルを削除するには ON DELETE CASCADE または先に子テーブルを削除する必要があります。DROP TABLE はデフォルトでごみ箱（RECYCLEBIN）に入り、FLASHBACK TABLE で復元可能です。
練習問題
問題 1 #OSLV-D8-001

以下のCREATE TABLE文で定義された制約の説明として正しいものはどれか。
```sql
CREATE TABLE orders (
order_id NUMBER(6) CONSTRAINT pk_orders PRIMARY KEY,
customer_id NUMBER(6) NOT NULL,
order_date DATE DEFAULT SYSDATE,
status VARCHAR2(10) CONSTRAINT chk_status
CHECK (status IN ('PENDING','SHIPPED','DONE'))
);
```

  • A. order_idは重複可能だがNOT NULL。statusはNULLも許可される
  • B. order_idは重複不可かつNOT NULL。order_dateは省略するとSYSDATEが入る。statusは3種の値のみ許可
  • C. customer_idはNULLを許可する。order_dateは省略するとNULLになる
  • D. PRIMARY KEY制約はNULLを許可するUNIQUE制約と同じ
解答・解説を見る

正解: B. order_idは重複不可かつNOT NULL。order_dateは省略するとSYSDATEが入る。statusは3種の値のみ許可

正解は「order_idは重複不可かつNOT NULL。order_dateは省略するとSYSDATEが入る。statusは3種の値のみ許可」である。PRIMARY KEY = UNIQUE + NOT NULL の制約。customer_idはNOT NULL制約があるのでNULL不可。order_dateのDEFAULT SYSDATEはINSERT時に値を省略した場合に現在日時が自動設定される。CHECK制約はstatusが'PENDING','SHIPPED','DONE'の3値のみ許可（NULLはCHECKをパスするためNOT NULLと組み合わせが推奨）。

VIEW・SEQUENCE・INDEX
VIEWCREATE VIEWSEQUENCENEXTVALCURRVALINDEXSYNONYM

VIEW（ビュー）

ビューは保存された SELECT 文です。テーブルのようにアクセスできます。

-- ビューの作成
CREATE VIEW emp_dept_vu AS
    SELECT e.EMPLOYEE_ID, e.LAST_NAME, e.DEPARTMENT_ID,
           d.DEPARTMENT_NAME
    FROM   EMPLOYEES e
    JOIN   DEPARTMENTS d
    ON     e.DEPARTMENT_ID = d.DEPARTMENT_ID;

-- ビューの使用
SELECT * FROM emp_dept_vu WHERE DEPARTMENT_NAME = 'Sales';

-- ビューの削除
DROP VIEW emp_dept_vu;

SEQUENCE（シーケンス）

シーケンスは連番を生成するオブジェクトです。主キーの自動採番に使います。

-- シーケンスの作成
CREATE SEQUENCE emp_seq
    START WITH 1
    INCREMENT BY 1
    MAXVALUE 99999
    NOCACHE
    NOCYCLE;

-- 次の値を取得（NEXTVAL）
INSERT INTO EMPLOYEES (EMPLOYEE_ID, LAST_NAME)
VALUES (emp_seq.NEXTVAL, 'Smith');

-- 現在の値を確認（CURRVAL: NEXTVAL を1度呼んだ後のみ使用可）
SELECT emp_seq.CURRVAL FROM DUAL;

INDEX（インデックス）

-- インデックスの作成
CREATE INDEX emp_lname_idx
ON EMPLOYEES (LAST_NAME);

-- インデックスの削除
DROP INDEX emp_lname_idx;

SYNONYM（シノニム）

-- パブリックシノニムの作成（DBA 権限が必要）
CREATE PUBLIC SYNONYM emp FOR EMPLOYEES;

-- プライベートシノニム
CREATE SYNONYM emp FOR EMPLOYEES;

-- シノニムの削除
DROP SYNONYM emp;
試験のポイント： CURRVAL は NEXTVAL を同じセッションで1回以上呼び出してから使用できます。シーケンスに CACHE を設定するとシステム障害時に番号が欠番になることがあります。INDEX は検索を高速化しますが、INSERT/UPDATE/DELETE は遅くなります。PRIMARY KEY と UNIQUE 制約を作成すると、自動的にインデックスが作成されます。
練習問題
問題 1 #OSLV-D8-002

以下のビュー(VIEW)に関する説明として正しいものはどれか。
```sql
CREATE OR REPLACE VIEW emp_view AS
SELECT employee_id, last_name, salary
FROM employees
WHERE salary > 10000;
```

  • A. ビューはデータを物理的にコピーして保存するため、ベーステーブル変更後も古いデータを返す
  • B. このビューからはINSERT/UPDATEができない（ビューは常に読み取り専用）
  • C. ビューは実データを持たない仮想表。ベーステーブルが更新されると自動的に最新データを反映する
  • D. OR REPLACEを使うと既存のビューを削除して新規作成するためエラーが発生する
解答・解説を見る

正解: C. ビューは実データを持たない仮想表。ベーステーブルが更新されると自動的に最新データを反映する

正解は「ビューは実データを持たない仮想表。ベーステーブルが更新されると自動的に最新データを反映する」である。ビューはSELECT定義を保存するだけで実データは持たない。参照時にSQLを実行するためベーステーブルの変更をリアルタイムに反映する。OR REPLACEは既存ビューがあっても削除せずに置き換える（エラーにならない）。単純ビュー（グループ関数・DISTINCT・JOIN・演算列などがない）はDML操作も可能。

問題 2 #OSLV-D8-003

以下のSQL文の実行結果として正しいものはどれか。
```sql
CREATE SEQUENCE emp_seq
START WITH 100
INCREMENT BY 10
MAXVALUE 200
NOCYCLE;

SELECT emp_seq.NEXTVAL FROM DUAL;
SELECT emp_seq.NEXTVAL FROM DUAL;
SELECT emp_seq.CURRVAL FROM DUAL;
```

  • A. 100, 110, 100
  • B. 100, 110, 110
  • C. 100, 100, 100
  • D. 110, 120, 120
解答・解説を見る

正解: B. 100, 110, 110

正解は「100, 110, 110」である。NEXTVALは呼び出すたびにシーケンスをINCREMENT BY分進めて現在値を返す。最初のNEXTVAL: START WITH 100 なので 100。2回目のNEXTVAL: 100 + 10 = 110。CURRVALは現在のシーケンス値を返す（進めない）ため 110。NOCYCLEはMAXVALUEに達した後さらに呼ぶとエラーになる設定（CYCLEならSTART WITHから再開）。CURRVALはNEXTVALを一度も呼んでいないセッションでは使用できない点に注意。

権限とロール

-- 権限付与
GRANT SELECT, INSERT ON EMPLOYEES TO app_user;

-- ロール作成と付与
CREATE ROLE report_reader;
GRANT SELECT ON EMPLOYEES TO report_reader;
GRANT report_reader TO app_user;

-- 権限の剥奪
REVOKE INSERT ON EMPLOYEES FROM app_user;

データ・ディクショナリ・ビュー

-- 自スキーマの表一覧
SELECT TABLE_NAME FROM USER_TABLES ORDER BY TABLE_NAME;

-- 参照可能な列定義
SELECT OWNER, TABLE_NAME, COLUMN_NAME, DATA_TYPE
FROM   ALL_TAB_COLUMNS
WHERE  TABLE_NAME = 'EMPLOYEES';

日時・タイムゾーン

-- 現在日時（セッションタイムゾーン）
SELECT CURRENT_DATE, CURRENT_TIMESTAMP FROM DUAL;

-- タイムゾーン変換
SELECT CURRENT_TIMESTAMP AT TIME ZONE '+00:00' AS UTC_TIME
FROM   DUAL;

-- INTERVAL の利用例
SELECT CURRENT_TIMESTAMP + INTERVAL '2' HOUR AS PLUS_2H
FROM   DUAL;
試験のポイント： 権限は最小権限で付与し、役割単位ではロールを使います。辞書ビュー（USER_/ALL_/DBA_）は参照範囲が異なります。CURRENT_TIMESTAMP はタイムゾーンを保持し、AT TIME ZONE で変換できます。
