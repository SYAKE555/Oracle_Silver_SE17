D5: 複数表の結合

Oracle Database SQL (1Z0-071) 対策
複数のテーブルを結合してデータを取得する JOIN 構文を学びます。内部結合、外部結合、自己結合など様々な結合方法を習得します。
INNER JOIN
INNER JOINJOINONUSINGNATURAL JOIN等結合

INNER JOIN の基本

INNER JOIN は両方のテーブルで条件が一致する行だけを返します。

-- ON 句を使った結合
SELECT e.LAST_NAME, e.DEPARTMENT_ID, d.DEPARTMENT_NAME
FROM   EMPLOYEES e
INNER JOIN DEPARTMENTS d
ON     e.DEPARTMENT_ID = d.DEPARTMENT_ID;

-- USING 句（同名の列で結合する場合）
SELECT LAST_NAME, DEPARTMENT_ID, DEPARTMENT_NAME
FROM   EMPLOYEES
JOIN   DEPARTMENTS
USING  (DEPARTMENT_ID);

-- NATURAL JOIN（同名列を自動で等結合）
SELECT LAST_NAME, DEPARTMENT_NAME
FROM   EMPLOYEES
NATURAL JOIN DEPARTMENTS;

旧来の等結合（Oracle 独自）

-- WHERE 句による等結合（非 ANSI 形式）
SELECT e.LAST_NAME, d.DEPARTMENT_NAME
FROM   EMPLOYEES e, DEPARTMENTS d
WHERE  e.DEPARTMENT_ID = d.DEPARTMENT_ID;
試験のポイント： USING 句を使う場合、結合に使った列にはテーブル名（またはエイリアス）を付けてはいけません。NATURAL JOIN は結合列を明示しないため、予期しない結合が起きる危険があります。INNER は省略可能（JOIN のみでも内部結合になる）。
練習問題
問題 1 #OSLV-D5-001

以下のSQL文の結果として正しいものはどれか。
```sql
SELECT e.last_name, d.department_name
FROM employees e
JOIN departments d ON e.department_id = d.department_id;
```
employeesに department_id = NULL の社員が2名いるとする。

  • A. department_idがNULLの社員2名もNULLとして結果に含まれる
  • B. department_idがNULLの社員2名は結果に含まれない
  • C. エラーになる（NULLを持つ列はJOINに使えない）
  • D. NULLとNULLが一致するとみなされdepartmentsのNULL行と結合される
解答・解説を見る

正解: B. department_idがNULLの社員2名は結果に含まれない

正解は「department_idがNULLの社員2名は結果に含まれない」である。INNER JOIN（JOINとだけ書いた場合もINNER JOIN）は結合条件に一致する行のみを返す。NULLは何とも等しくないため（NULL = NULLはUNKNOWN）、ON e.department_id = d.department_idはNULLの場合に一致しない。NULLの社員も含めたい場合はLEFT OUTER JOINを使う。選択肢DはNULL同士を等しいとみなすことはないため誤り。

問題 2 #OSLV-D5-002

以下のSQL文の実行結果の行数として正しいものはどれか。
```sql
SELECT e.last_name, d.department_name
FROM employees e
LEFT OUTER JOIN departments d
ON e.department_id = d.department_id;
```
employees: 107行（うち department_id = NULL が2行）、departments: 27行

  • A. 107行（NULLの社員2名はdepartment_nameがNULLで表示）
  • B. 105行（NULLの社員は除外）
  • C. 27行（departmentsの行数に合わせる）
  • D. 134行（107 + 27）
解答・解説を見る

正解: A. 107行（NULLの社員2名はdepartment_nameがNULLで表示）

正解は「107行（NULLの社員2名はdepartment_nameがNULLで表示）」である。LEFT OUTER JOINは左表（employees）の全行を必ず結果に含める。右表（departments）で対応する行がない場合（NULLの社員の場合）、右表の列はNULLとして表示される。したがって employees の全107行が返され、department_id = NULLの2名はdepartment_nameがNULLとなる。INNER JOINなら105行、RIGHT OUTER JOINなら右表基準。

問題 3 #OSLV-D5-003

以下のSQL文（自己結合）の目的として正しいものはどれか。
```sql
SELECT e.last_name AS 社員名,
m.last_name AS 上司名
FROM employees e
JOIN employees m ON e.manager_id = m.employee_id;
```

  • A. 全社員の部下一覧を表示する
  • B. manager_idがNULLの社員のみを表示する
  • C. 社員とその上司の名前を同じテーブルから取得する
  • D. エラーになる（同じテーブルをJOINできない）
解答・解説を見る

正解: C. 社員とその上司の名前を同じテーブルから取得する

正解は「社員とその上司の名前を同じテーブルから取得する」である。自己結合（SELF JOIN）は同一テーブルに対して別名（エイリアス）を2つ付けてJOINする手法。ここではemployeesテーブルをe（社員側）とm（上司側）として結合し、e.manager_id = m.employee_idで社員の上司IDと上司のemployee_idを一致させる。manager_idがNULLの社員（最上位管理者）はINNER JOINなので結果に含まれない。LEFT JOINにすれば全社員＋上司名NULLの行が含まれる。

LEFT OUTER JOINRIGHT OUTER JOINFULL OUTER JOIN外部結合

外部結合（OUTER JOIN）

一方のテーブルに一致する行がなくても、NULL として結果に含めます。

種類説明
LEFT OUTER JOIN左テーブルの全行を返す。右に一致なければ NULL
RIGHT OUTER JOIN右テーブルの全行を返す。左に一致なければ NULL
FULL OUTER JOIN両テーブルの全行を返す。一致なければ NULL
-- 部署なし従業員も含めて表示（LEFT OUTER JOIN）
SELECT e.LAST_NAME, d.DEPARTMENT_NAME
FROM   EMPLOYEES e
LEFT OUTER JOIN DEPARTMENTS d
ON     e.DEPARTMENT_ID = d.DEPARTMENT_ID;

-- 従業員のいない部署も含めて表示（RIGHT OUTER JOIN）
SELECT e.LAST_NAME, d.DEPARTMENT_NAME
FROM   EMPLOYEES e
RIGHT OUTER JOIN DEPARTMENTS d
ON     e.DEPARTMENT_ID = d.DEPARTMENT_ID;

-- Oracle 独自の外部結合記法（(+) 記号）
SELECT e.LAST_NAME, d.DEPARTMENT_NAME
FROM   EMPLOYEES e, DEPARTMENTS d
WHERE  e.DEPARTMENT_ID = d.DEPARTMENT_ID(+);
試験のポイント： Oracle 独自の (+) 記法では、NULL を補完したい側（右テーブル相当）に (+) を付けます。FULL OUTER JOIN は (+) 記法では表現できません。OUTER は省略可能（LEFT JOIN でも外部結合になる）。

自己結合とクロス結合
自己結合SELF JOINCROSS JOINクロス結合エイリアス

自己結合（SELF JOIN）

同じテーブルを異なるエイリアスで2回参照して結合します。階層データ（上司-部下など）の取得に使います。

-- 従業員とその上司の名前を表示
SELECT e.LAST_NAME AS 従業員,
       m.LAST_NAME AS 上司
FROM   EMPLOYEES e
LEFT JOIN EMPLOYEES m
ON     e.MANAGER_ID = m.EMPLOYEE_ID;

クロス結合（CROSS JOIN）

CROSS JOIN は全行の組み合わせを返します（直積）。結果行数 = テーブル1の行数 x テーブル2の行数。

-- CROSS JOIN（ANSI 形式）
SELECT e.LAST_NAME, d.DEPARTMENT_NAME
FROM   EMPLOYEES e
CROSS JOIN DEPARTMENTS d;

-- 旧来の表記（WHERE 句なし）
SELECT e.LAST_NAME, d.DEPARTMENT_NAME
FROM   EMPLOYEES e, DEPARTMENTS d;
試験のポイント： 自己結合では必ずテーブルエイリアスが必要です。クロス結合は意図せず WHERE を省略した場合にも発生するため注意が必要です。上司が存在しない場合（社長など）は MANAGER_ID が NULL になるため、INNER JOIN ではなく LEFT JOIN を使うと全員が表示されます。
