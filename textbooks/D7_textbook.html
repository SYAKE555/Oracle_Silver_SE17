D7: DML（データ操作言語）

Oracle Database SQL (1Z0-071) 対策
INSERT, UPDATE, DELETE でデータを変更する方法と、COMMIT/ROLLBACK によるトランザクション管理を学びます。
コマンド覚え方リファレンス
コマンド/句 意味（日本語） 覚え方（語呂合わせや連想） 主な用途 実務での使用 試験での出方（頻出パターン）
INSERT INTO テーブルに新しい行を追加する 「INSERTはデータを差し込む—テーブルに行を挿入」 新規レコードの登録 使う（アプリケーションでの新規データ登録に必須） 列リスト省略時の列順一致、サブクエリINSERTのVALUES不要
UPDATE...SET 既存の行のデータを変更する 「UPDATEはデータをセット（SET）し直す」 既存レコードの値変更 使う（データ修正・一括更新など頻繁に使用） WHERE省略で全行更新、SET句での複数列指定
DELETE FROM 条件に一致する行をテーブルから削除する 「DELETEはデータを消す—WHEREがないと全消し」 不要レコードの削除 使う（論理削除ではなく物理削除が必要な場合） TRUNCATEとの違い（DML/DDL、ROLLBACK可否）
TRUNCATE テーブルの全データを高速削除する（DDL） 「TRUNCATEは切り捨て—高速だが取り消し不可」 テーブルの全データ一括削除・初期化 条件付き（テスト環境や初期化処理で使用、本番は慎重に） DDLなのでROLLBACK不可、暗黙COMMITが発生する
COMMIT トランザクションの変更を確定・永続化する 「COMMITはコミット（確約）—変更を確定して公開」 DML変更の確定 使う（変更を反映するために必須） COMMIT後はROLLBACK不可、他のセッションに変更が見える
ROLLBACK トランザクションの変更を取り消す 「ROLLBACKはロール（巻き戻し）—変更をなかったことに」 誤操作やエラー時の変更取り消し 使う（エラー時の安全なデータ復元） COMMIT後は不可、DDL実行後も不可（暗黙COMMIT）
SAVEPOINT トランザクション内の中間保存点を設定する 「SAVEPOINTはセーブポイント—ゲームの途中セーブ」 長いトランザクションの途中でのロールバック地点設定 条件付き（複数ステップのバッチ処理で活用） ROLLBACK TO SAVEPOINTで特定時点まで戻れること
MERGE INTO 条件一致で UPDATE、不一致で INSERT を1文で実行（UPSERT） 「MERGEは合体—UPDATE と INSERT を1つにまとめる」 マスタデータの同期処理、差分更新 使う（データ移行や定期同期バッチで活用） WHEN MATCHED/WHEN NOT MATCHEDの使い分け
略称・用語定義
略称 正式名称 意味
DML Data Manipulation Language（データ操作言語） テーブルのデータを操作するSQL文の総称。
INSERT、UPDATE、DELETE、MERGEが該当する。
COMMIT前はROLLBACK可能。
TCL Transaction Control Language（トランザクション制御言語） トランザクションを制御するSQL文の総称。
COMMIT、ROLLBACK、SAVEPOINTが該当する。
DMLの変更を確定または取り消す。
COMMIT Commit（確定・コミット） 現在のトランザクションで行われたすべての変更を永続化する。
COMMITされた変更は他のセッションから参照可能になり、ROLLBACKで取り消せなくなる。
ROLLBACK Rollback（巻き戻し・取り消し） 現在のトランザクションで行われた変更を取り消し、直前のCOMMIT時点に戻す。
ROLLBACK TO SAVEPOINTで特定の中間点まで部分的に戻すことも可能。
SAVEPOINT Savepoint（セーブポイント・中間保存点） トランザクション内に名前付きの中間保存点を設定する。
ROLLBACK TO <名前> で、その時点以降の変更のみを取り消せる。
MERGE Merge（マージ・統合） UPSERT（UPDATE + INSERT）操作を1文で実現するSQL文。
ON条件で一致する行はUPDATE、一致しない行はINSERTする。
Oracle 9i以降で使用可能。
INSERT と UPDATE
INSERTUPDATESETVALUESINSERT INTO SELECT

INSERT 文

テーブルに新しい行を追加します。

-- 全列に値を挿入（列リストを省略）
INSERT INTO DEPARTMENTS
VALUES (280, 'New Dept', 100, 1700);
-- 実行結果例：
-- 1 行が挿入されました。
-- （DEPARTMENT_ID=280の行がDEPARTMENTSテーブルに追加される）

-- 指定した列のみ挿入
INSERT INTO DEPARTMENTS (DEPARTMENT_ID, DEPARTMENT_NAME)
VALUES (290, 'Another Dept');
-- 実行結果例：
-- 1 行が挿入されました。
-- （MANAGER_IDとLOCATION_IDはNULLで挿入される）

-- サブクエリを使った一括挿入
INSERT INTO SALES_REPS (EMP_ID, NAME, SALARY)
SELECT EMPLOYEE_ID, LAST_NAME, SALARY
FROM   EMPLOYEES
WHERE  JOB_ID = 'SA_REP';
-- 実行結果例：
-- 35 行が挿入されました。
-- （JOB_ID='SA_REP'の全社員がSALES_REPSテーブルに一括挿入される。VALUESは不要）

UPDATE 文

既存の行のデータを変更します。
WHERE がないと全行が更新されます。

-- 特定の行を更新
UPDATE EMPLOYEES
SET    SALARY = SALARY * 1.1,
       COMMISSION_PCT = 0.05
WHERE  DEPARTMENT_ID = 50;
-- 実行結果例：
-- 45 行が更新されました。
-- （部署50の全社員のSALARYが10%増加し、COMMISSION_PCTが0.05に設定される）

-- サブクエリを使った更新
UPDATE EMPLOYEES
SET    DEPARTMENT_ID = (
           SELECT DEPARTMENT_ID
           FROM   DEPARTMENTS
           WHERE  DEPARTMENT_NAME = 'Sales'
       )
WHERE  EMPLOYEE_ID = 100;
-- 実行結果例：
-- 1 行が更新されました。
-- （社員ID=100のDEPARTMENT_IDがSalesのDEPARTMENT_IDに変更される）
試験のポイント： INSERT の列リストを省略する場合は、テーブル定義の列順に全列分の値を指定する必要があります。
UPDATE で WHERE を省略すると全行が更新されます（意図しない全件更新に注意）。
練習問題
問題 1 #OSLV-D7-001

以下のSQL操作を実行した後の状態として正しいものはどれか。
```sql
INSERT INTO departments VALUES (280, 'Training', NULL, NULL);
SAVEPOINT sp1;
UPDATE departments SET department_name = 'Education' WHERE department_id = 280;
ROLLBACK TO sp1;
```

  • A. department_id=280 の行は存在しない（ROLLBACKで全て取り消された）
  • B. department_id=280 のdepartment_nameは 'Training' になる（UPDATEがロールバックされた）
  • C. department_id=280 のdepartment_nameは 'Education' のままになる
  • D. エラーになる（SAVEPOINTとROLLBACKは同一トランザクションで使えない）
解答・解説を見る

正解: B. department_id=280 のdepartment_nameは 'Training' になる（UPDATEがロールバックされた）

正解は「department_id=280 のdepartment_nameは 'Training' になる（UPDATEがロールバックされた）」である。
SAVEPOINT sp1はsp1という中間保存点をトランザクション内に設定する。
ROLLBACK TO sp1はsp1以降の変更（UPDATEのみ）を取り消し、sp1設定時点（INSERTの後）の状態に戻す。
したがってINSERTは残り、UPDATEは取り消される。
ROLLBACK（TO なし）は全変更を取り消す。
COMMIT後はROLLBACKできない。
Oracle SQL Reference §SAVEPOINT, ROLLBACK参照。

問題 2 #OSLV-D7-003

以下のUPDATE文の実行結果として正しいものはどれか。
```sql
UPDATE employees
SET salary = salary * 1.1,
commission_pct = NVL(commission_pct, 0) + 0.05
WHERE department_id = 80;
```
department_id=80 の社員5名のうち commission_pctがNULLの社員が2名いるとする。

  • A. commission_pctがNULLの社員はUPDATE対象外になる
  • B. NVLはUPDATE文では使えないためエラーになる
  • C. 5名全員のsalaryが10%増加し、NULLの社員のcommission_pctは0.05になる
  • D. commission_pctがNULLの社員のsalaryはNULLになる
解答・解説を見る

正解: C. 5名全員のsalaryが10%増加し、NULLの社員のcommission_pctは0.05になる

正解は「5名全員のsalaryが10%増加し、NULLの社員のcommission_pctは0.05になる」である。
SET句では単一行関数（NVLなど）を使用できる。
NVL(commission_pct, 0)はcommission_pctがNULLの場合0を返すので、0 + 0.05 = 0.05 が設定される。
NULL以外の社員は既存値 + 0.05 となる。
salary = salary * 1.1 も全行に適用される。
WHERE句はdepartment_id = 80 の絞り込みのみ。

DELETE・TRUNCATE とトランザクション
DELETETRUNCATECOMMITROLLBACKSAVEPOINTトランザクション

DELETE 文

-- 条件に合う行を削除
DELETE FROM DEPARTMENTS
WHERE  DEPARTMENT_ID = 290;
-- 実行結果例：
-- 1 行が削除されました。
-- （DEPARTMENT_ID=290の行のみ削除される。COMMIT前はROLLBACK可能）

-- 全行削除（ROLLBACK 可能）
DELETE FROM COPY_EMPLOYEES;
-- 実行結果例：
-- 107 行が削除されました。
-- （全行削除だがDMLなのでCOMMIT前はROLLBACK可能。TRUNCATEより低速）

TRUNCATE 文

-- テーブルの全データを高速削除（DDL、ROLLBACK 不可）
TRUNCATE TABLE COPY_EMPLOYEES;
-- 実行結果例：
-- テーブルが切り捨てられました。
-- （全行が即時削除される。DDLのため暗黙COMMITが発生し、ROLLBACKは不可）
比較DELETETRUNCATE
分類DMLDDL
ROLLBACK可能不可
WHERE 句使用可能使用不可（全件削除のみ）
処理速度低速（ログ記録あり）高速（ログ記録なし）
AUTOCOMMITなしあり（暗黙的COMMIT）

トランザクション制御

-- データ変更
UPDATE EMPLOYEES SET SALARY = 5000 WHERE EMPLOYEE_ID = 100;
-- 実行結果例：1 行が更新されました。

-- セーブポイント設定
SAVEPOINT update_done;
-- 実行結果例：セーブポイントが作成されました。

-- 追加の変更
DELETE FROM EMPLOYEES WHERE EMPLOYEE_ID = 200;
-- 実行結果例：1 行が削除されました。

-- セーブポイントまで戻す
ROLLBACK TO update_done;
-- 実行結果例：ロールバックが完了しました。
-- （DELETEだけが取り消され、UPDATEはSAVEPOINT前なので残る）

-- 確定
COMMIT;
-- 実行結果例：コミットが完了しました。
-- （UPDATEが永続化される。この後ROLLBACKしても元に戻せない）
試験のポイント： TRUNCATE は DDL なので暗黙的 COMMIT が行われます。
ROLLBACK できません。
DDL 文（CREATE, ALTER, DROP 等）を実行すると、直前の未コミットの DML が自動的に COMMIT されます。
SAVEPOINT はトランザクション内の特定の時点に戻すためのマーカーです。

問題 2 #OSLV-D7-002

DELETEとTRUNCATEの違いとして正しいものはどれか。

  • A. TRUNCATEはWHERE句で削除する行を指定できる
  • B. TRUNCATEはDDL文でありROLLBACKできない。
    DELETEはDML文でROLLBACK可能
  • C. DELETEはテーブル定義ごと削除するがTRUNCATEはデータのみ削除する
  • D. TRUNCATEもDELETEも同じくROLLBACKできる
解答・解説を見る

正解: B. TRUNCATEはDDL文でありROLLBACKできない。
DELETEはDML文でROLLBACK可能

正解は「TRUNCATEはDDL文でありROLLBACKできない。
DELETEはDML文でROLLBACK可能」である。
TRUNCATE TABLEはDDL（データ定義言語）であり、実行時に暗黙的COMMITが行われるためROLLBACKできない。
また全行を高速に削除するがWHERE句は使えない。
DELETE FROMはDML（データ操作言語）であり、WHERE句で対象行を指定でき、COMMIT前ならROLLBACKで取り消せる。
テーブル定義を削除するのはDROP TABLE。

MERGE とマルチテーブル挿入
MERGEWHEN MATCHEDWHEN NOT MATCHEDマルチテーブルINSERT

MERGE 文（UPSERT）

一致すれば UPDATE、なければ INSERT を1文で実行します。

MERGE INTO SALES_TARGET t
USING (SELECT 10 AS DEPT_ID, 1200000 AS TARGET_AMT FROM DUAL) s
ON (t.DEPT_ID = s.DEPT_ID)
WHEN MATCHED THEN
  UPDATE SET t.TARGET_AMT = s.TARGET_AMT
WHEN NOT MATCHED THEN
  INSERT (DEPT_ID, TARGET_AMT)
  VALUES (s.DEPT_ID, s.TARGET_AMT);
-- 実行結果例：
-- DEPT_ID=10 の行が既に存在する場合 → 1 行が更新されました。
-- DEPT_ID=10 の行が存在しない場合  → 1 行が挿入されました。
-- （ON条件の一致・不一致によってUPDATEかINSERTが自動選択される）

マルチテーブル INSERT

1つのソース結果を条件で複数テーブルへ振り分けます。

INSERT ALL
  WHEN SALARY >= 10000 THEN
    INTO HIGH_SAL (EMP_ID, SALARY) VALUES (EMPLOYEE_ID, SALARY)
  WHEN SALARY < 10000 THEN
    INTO LOW_SAL (EMP_ID, SALARY) VALUES (EMPLOYEE_ID, SALARY)
SELECT EMPLOYEE_ID, SALARY
FROM   EMPLOYEES;
-- 実行結果例：
-- 107 行が挿入されました。
-- （給与10000以上の社員はHIGH_SALへ、10000未満の社員はLOW_SALへ振り分けられる。
--  合計挿入行数はソースの全行数に等しい）
試験のポイント： MERGE は ON 条件で一致判定し、WHEN MATCHED / WHEN NOT MATCHED を使い分けます。
大量同期処理で UPDATE+INSERT を分けるより保守しやすいケースが多いです。
