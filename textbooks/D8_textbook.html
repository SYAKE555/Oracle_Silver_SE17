D8: DDL・オブジェクト管理

Oracle Database SQL (1Z0-071) 対策
テーブルやオブジェクトの作成・変更・削除など、データ定義言語（DDL）とデータベースオブジェクトの管理を学びます。
コマンド覚え方リファレンス
コマンド/句 意味（日本語） 覚え方（語呂合わせや連想） 主な用途 実務での使用 試験での出方（頻出パターン）
CREATE TABLE テーブルを新規作成する 「CREATEは創造—テーブルという器を作る」 新しいテーブルの定義・作成 使う（スキーマ設計の基本） 制約の定義方法（列レベル/テーブルレベル）、DEFAULTは制約ではない
ALTER TABLE 既存テーブルの定義を変更する 「ALTERは変更—テーブルの設計図を書き直す」 列追加・変更・削除、制約の追加・削除 使う（仕様変更時に既存テーブルを変更） ADD/MODIFY/DROP COLUMNの使い分け
DROP TABLE テーブルを削除する（データごと） 「DROPは落とす—テーブルをごみ箱へ投げ捨てる」 不要なテーブルの完全削除 条件付き（本番環境では慎重に、PURGEオプションに注意） ごみ箱（RECYCLEBIN）とFLASHBACK、PURGEで即時削除
CONSTRAINT テーブルのデータ整合性ルールを定義する 「CONSTRAINTは制約—データのルール違反を防ぐ番人」 データ品質・整合性の保証 使う（PK、FK、NOT NULL、UNIQUEは必須） 列レベルvs.テーブルレベルの記述場所、複合PKはテーブルレベルのみ
PRIMARY KEY 行を一意に識別する主キー制約（NOT NULL + UNIQUE） 「PRIMARY KEYは主役の鍵—絶対に一意でNULLは許さない」 テーブルの主キー定義 使う（すべてのテーブルに設定が推奨） 1テーブルに1つのみ、自動的にインデックスが作成される
FOREIGN KEY 他テーブルの主キーを参照する外部キー制約 「FOREIGN KEYは外国のパスポート—他テーブルのIDを参照」 テーブル間の参照整合性の保証 使う（関連テーブル間の整合性確保） ON DELETE CASCADE/SET NULL、親テーブル削除順序
UNIQUE 列の値を一意に保つ制約（NULLは複数可） 「UNIQUEはユニーク—同じ値は2つ存在できない（NULLを除く）」 メールアドレスや社員番号などの重複防止 使う（業務キーの重複防止） NULLは複数行に存在可、自動的にインデックスが作成される
NOT NULL 列にNULL値を禁止する制約 「NOT NULLは空欄禁止—必ず値を入れること」 必須入力項目の定義 使う（必須項目には必ず設定） 列レベル制約のみ（テーブルレベルでは定義不可）
CHECK 列の値が指定した条件を満たすことを保証する制約 「CHECKは検問—条件に合わない値は入れさせない」 値の範囲・形式の制限 使う（ステータス値や数値範囲の制限） NULLはCHECKをパスする（NOT NULLとの組み合わせが推奨）
CREATE VIEW 仮想表（ビュー）を作成する 「VIEWはのぞき窓—テーブルを安全に見せる仮想の窓口」 セキュリティ、複雑クエリの簡略化 使う（アクセス制御や再利用可能なクエリ定義） 実データを持たない、OR REPLACEで再定義可能
CREATE SEQUENCE 連番を生成するシーケンスオブジェクトを作成する 「SEQUENCEは番号発券機—呼ぶたびに次の番号を渡す」 主キーの自動採番 使う（INSERTでの一意ID生成） NEXTVALで次の値、CURRVALは同一セッションでNEXTVAL後のみ使用可
CREATE INDEX 検索を高速化するインデックスを作成する 「INDEXは本の索引—探す場所をすぐに特定できる」 クエリパフォーマンスの向上 使う（頻繁に検索される列に設定） INSERT/UPDATE/DELETEは遅くなる、PK/UNIQUEで自動作成
CREATE SYNONYM オブジェクトの別名（シノニム）を作成する 「SYNONYMは別名—スキーマ名を省略してアクセス可能に」 他スキーマのオブジェクトへの簡単アクセス 使う（スキーマ名を隠蔽したい場合） PUBLIC SYNONYMはDBA権限が必要、PRIVATE SYNONYMは不要
GRANT ユーザーやロールに権限を付与する 「GRANTは認可—アクセス許可証を発行する」 ユーザーへのアクセス権限付与 使う（セキュリティ管理の基本） WITH GRANT OPTIONで権限の再付与を許可
REVOKE ユーザーやロールから権限を取り消す 「REVOKEは取り消し—一度渡した許可証を回収する」 不要になった権限の削除 使う（退職者や役割変更時に権限を整理） WITH GRANT OPTIONで付与された権限も連鎖的に取り消される
略称・用語定義
略称 正式名称 意味
DDL Data Definition Language（データ定義言語） データベースオブジェクトの構造を定義・変更・削除するSQL文の総称。
CREATE、ALTER、DROP、TRUNCATEが該当する。
実行時に暗黙COMMITが発生し、ROLLBACKできない。
DCL Data Control Language（データ制御言語） データベースへのアクセス権限を制御するSQL文の総称。
GRANTとREVOKEが該当する。
PK Primary Key（主キー） テーブル内の各行を一意に識別する列（または列の組み合わせ）。
NOT NULL と UNIQUE の両方の性質を持つ。
1テーブルに1つのみ定義可能。
自動的にインデックスが作成される。
FK Foreign Key（外部キー） 別テーブルの主キー（またはユニークキー）を参照する列。
参照整合性を保証し、参照先に存在しない値やNULL以外は挿入できない。
DBA Database Administrator（データベース管理者） Oracleデータベースの管理者ロール。
DBA_プレフィックスの辞書ビューを参照できる最高権限ユーザー。
CREATE PUBLIC SYNONYM などの特権操作が可能。
USER_ / ALL_ / DBA_ 辞書ビューのプレフィックス（接頭語） USER_：自分が所有するオブジェクトのみ参照可能。
ALL_：自分がアクセス権を持つすべてのオブジェクトを参照可能。
DBA_：データベース内のすべてのオブジェクトを参照可能（DBA権限が必要）。

CREATE TABLE の基本

CREATE TABLE EMPLOYEES (
    EMPLOYEE_ID   NUMBER(6)     CONSTRAINT emp_pk PRIMARY KEY,
    FIRST_NAME    VARCHAR2(20),
    LAST_NAME     VARCHAR2(25)  CONSTRAINT emp_lname_nn NOT NULL,
    EMAIL         VARCHAR2(25)  CONSTRAINT emp_email_uk UNIQUE,
    HIRE_DATE     DATE          DEFAULT SYSDATE,
    SALARY        NUMBER(8,2)   CONSTRAINT emp_salary_ck CHECK (SALARY > 0),
    DEPARTMENT_ID NUMBER(4)     CONSTRAINT emp_dept_fk
                               REFERENCES DEPARTMENTS(DEPARTMENT_ID)
);
-- 実行結果例：
-- テーブルが作成されました。
-- （各制約が自動的に有効化される。PRIMARY KEY と UNIQUE には自動でインデックスが作成される）

ALTER TABLE / DROP TABLE

-- 列の追加
ALTER TABLE EMPLOYEES ADD (NOTES VARCHAR2(100));
-- 実行結果例：
-- テーブルが変更されました。
-- （NOTES列がNULL可で追加される）

-- 列の変更
ALTER TABLE EMPLOYEES MODIFY (FIRST_NAME VARCHAR2(30));
-- 実行結果例：
-- テーブルが変更されました。
-- （FIRST_NAMEのサイズが20から30に拡張される。既存データがある列のサイズ縮小はエラーになる場合がある）

-- 列の削除
ALTER TABLE EMPLOYEES DROP COLUMN NOTES;
-- 実行結果例：
-- テーブルが変更されました。
-- （NOTES列とそのデータが削除される）

-- テーブルの削除（データも削除）
DROP TABLE COPY_EMPLOYEES;
-- 実行結果例：
-- テーブルが削除されました。
-- （テーブルはごみ箱（RECYCLEBIN）に入る。FLASHBACK TABLE で復元可能）

-- テーブルの削除（PURGE: ごみ箱に入れない）
DROP TABLE COPY_EMPLOYEES PURGE;
-- 実行結果例：
-- テーブルが削除されました。
-- （ごみ箱に入らず即時削除。FLASHBACK TABLE による復元は不可）
試験のポイント： PRIMARY KEY は1テーブルに1つだけ設定可能です。
UNIQUE は複数可。
FOREIGN KEY の参照先テーブルを削除するには ON DELETE CASCADE または先に子テーブルを削除する必要があります。
DROP TABLE はデフォルトでごみ箱（RECYCLEBIN）に入り、FLASHBACK TABLE で復元可能です。
練習問題
問題 1 #OSLV-D8-001

以下のCREATE TABLE文で定義された制約の説明として正しいものはどれか。
```sql
CREATE TABLE orders (
order_id NUMBER(6) CONSTRAINT pk_orders PRIMARY KEY,
customer_id NUMBER(6) NOT NULL,
order_date DATE DEFAULT SYSDATE,
status VARCHAR2(10) CONSTRAINT chk_status
CHECK (status IN ('PENDING','SHIPPED','DONE'))
);
```

  • A. order_idは重複可能だがNOT NULL。
    statusはNULLも許可される
  • B. order_idは重複不可かつNOT NULL。
    order_dateは省略するとSYSDATEが入る。
    statusは3種の値のみ許可
  • C. customer_idはNULLを許可する。
    order_dateは省略するとNULLになる
  • D. PRIMARY KEY制約はNULLを許可するUNIQUE制約と同じ
解答・解説を見る

正解: B. order_idは重複不可かつNOT NULL。
order_dateは省略するとSYSDATEが入る。
statusは3種の値のみ許可

正解は「order_idは重複不可かつNOT NULL。
order_dateは省略するとSYSDATEが入る。
statusは3種の値のみ許可」である。
PRIMARY KEY = UNIQUE + NOT NULL の制約。
customer_idはNOT NULL制約があるのでNULL不可。
order_dateのDEFAULT SYSDATEはINSERT時に値を省略した場合に現在日時が自動設定される。
CHECK制約はstatusが'PENDING','SHIPPED','DONE'の3値のみ許可（NULLはCHECKをパスするためNOT NULLと組み合わせが推奨）。

VIEW（ビュー）

ビューは保存された SELECT 文です。
テーブルのようにアクセスできます。

-- ビューの作成
CREATE VIEW emp_dept_vu AS
    SELECT e.EMPLOYEE_ID, e.LAST_NAME, e.DEPARTMENT_ID,
           d.DEPARTMENT_NAME
    FROM   EMPLOYEES e
    JOIN   DEPARTMENTS d
    ON     e.DEPARTMENT_ID = d.DEPARTMENT_ID;
-- 実行結果例：
-- ビューが作成されました。
-- （実データは保存されない。SELECTのたびにベーステーブルを参照する）

-- ビューの使用
SELECT * FROM emp_dept_vu WHERE DEPARTMENT_NAME = 'Sales';
-- 実行結果例：
-- EMPLOYEE_ID LAST_NAME            DEPARTMENT_ID DEPARTMENT_NAME
-- ----------- -------------------- ------------- ---------------
--         145 Russell                         80 Sales
--         146 Partners                        80 Sales
-- ...（ビュー定義のSELECTが実行され、最新データが返る）

-- ビューの削除
DROP VIEW emp_dept_vu;
-- 実行結果例：
-- ビューが削除されました。

SEQUENCE（シーケンス）

シーケンスは連番を生成するオブジェクトです。
主キーの自動採番に使います。

-- シーケンスの作成
CREATE SEQUENCE emp_seq
    START WITH 1
    INCREMENT BY 1
    MAXVALUE 99999
    NOCACHE
    NOCYCLE;
-- 実行結果例：
-- シーケンスが作成されました。

-- 次の値を取得（NEXTVAL）
INSERT INTO EMPLOYEES (EMPLOYEE_ID, LAST_NAME)
VALUES (emp_seq.NEXTVAL, 'Smith');
-- 実行結果例：
-- 1 行が挿入されました。
-- （EMPLOYEE_ID に emp_seq の次の値（初回は1）が自動設定される）

-- 現在の値を確認（CURRVAL: NEXTVAL を1度呼んだ後のみ使用可）
SELECT emp_seq.CURRVAL FROM DUAL;
-- 実行結果例：
-- CURRVAL
-- -------
--       1
-- （同一セッション内でNEXTVALを呼んだ後のみ使用可。呼ぶたびに値は進まない）

INDEX（インデックス）

-- インデックスの作成
CREATE INDEX emp_lname_idx
ON EMPLOYEES (LAST_NAME);
-- 実行結果例：
-- インデックスが作成されました。
-- （LAST_NAME列の検索が高速化される。INSERT/UPDATE/DELETEはやや低速になる）

-- インデックスの削除
DROP INDEX emp_lname_idx;
-- 実行結果例：
-- インデックスが削除されました。

SYNONYM（シノニム）

-- パブリックシノニムの作成（DBA 権限が必要）
CREATE PUBLIC SYNONYM emp FOR EMPLOYEES;
-- 実行結果例：
-- シノニムが作成されました。
-- （すべてのユーザーがスキーマ名なしで "emp" としてEMPLOYEESにアクセスできる）

-- プライベートシノニム
CREATE SYNONYM emp FOR EMPLOYEES;
-- 実行結果例：
-- シノニムが作成されました。
-- （作成したユーザーのみが "emp" としてEMPLOYEESにアクセスできる）

-- シノニムの削除
DROP SYNONYM emp;
-- 実行結果例：
-- シノニムが削除されました。
-- （シノニムを削除してもベーステーブルのデータは削除されない）
試験のポイント： CURRVAL は NEXTVAL を同じセッションで1回以上呼び出してから使用できます。
シーケンスに CACHE を設定するとシステム障害時に番号が欠番になることがあります。
INDEX は検索を高速化しますが、INSERT/UPDATE/DELETE は遅くなります。
PRIMARY KEY と UNIQUE 制約を作成すると、自動的にインデックスが作成されます。
練習問題
問題 1 #OSLV-D8-002

以下のビュー(VIEW)に関する説明として正しいものはどれか。
```sql
CREATE OR REPLACE VIEW emp_view AS
SELECT employee_id, last_name, salary
FROM employees
WHERE salary > 10000;
```

  • A. ビューはデータを物理的にコピーして保存するため、ベーステーブル変更後も古いデータを返す
  • B. このビューからはINSERT/UPDATEができない（ビューは常に読み取り専用）
  • C. ビューは実データを持たない仮想表。
    ベーステーブルが更新されると自動的に最新データを反映する
  • D. OR REPLACEを使うと既存のビューを削除して新規作成するためエラーが発生する
解答・解説を見る

正解: C. ビューは実データを持たない仮想表。
ベーステーブルが更新されると自動的に最新データを反映する

正解は「ビューは実データを持たない仮想表。
ベーステーブルが更新されると自動的に最新データを反映する」である。
ビューはSELECT定義を保存するだけで実データは持たない。
参照時にSQLを実行するためベーステーブルの変更をリアルタイムに反映する。
OR REPLACEは既存ビューがあっても削除せずに置き換える（エラーにならない）。
単純ビュー（グループ関数・DISTINCT・JOIN・演算列などがない）はDML操作も可能。

問題 2 #OSLV-D8-003

以下のSQL文の実行結果として正しいものはどれか。
```sql
CREATE SEQUENCE emp_seq
START WITH 100
INCREMENT BY 10
MAXVALUE 200
NOCYCLE;

SELECT emp_seq.NEXTVAL FROM DUAL;
SELECT emp_seq.NEXTVAL FROM DUAL;
SELECT emp_seq.CURRVAL FROM DUAL;
```

  • A. 100, 110, 100
  • B. 100, 110, 110
  • C. 100, 100, 100
  • D. 110, 120, 120
解答・解説を見る

正解: B. 100, 110, 110

正解は「100, 110, 110」である。
NEXTVALは呼び出すたびにシーケンスをINCREMENT BY分進めて現在値を返す。
最初のNEXTVAL: START WITH 100 なので 100。
2回目のNEXTVAL: 100 + 10 = 110。
CURRVALは現在のシーケンス値を返す（進めない）ため 110。
NOCYCLEはMAXVALUEに達した後さらに呼ぶとエラーになる設定（CYCLEならSTART WITHから再開）。
CURRVALはNEXTVALを一度も呼んでいないセッションでは使用できない点に注意。

権限とロール

-- 権限付与
GRANT SELECT, INSERT ON EMPLOYEES TO app_user;
-- 実行結果例：
-- 権限付与が成功しました。
-- （app_userはEMPLOYEESテーブルのSELECTとINSERTが可能になる）

-- ロール作成と付与
CREATE ROLE report_reader;
GRANT SELECT ON EMPLOYEES TO report_reader;
GRANT report_reader TO app_user;
-- 実行結果例：
-- ロールが作成されました。
-- 権限付与が成功しました。
-- 権限付与が成功しました。
-- （ロールを介してapp_userにSELECT権限が付与される）

-- 権限の剥奪
REVOKE INSERT ON EMPLOYEES FROM app_user;
-- 実行結果例：
-- 権限が取り消されました。
-- （app_userのINSERT権限が削除される。SELECT権限は残る）

日時・タイムゾーン

-- 現在日時（セッションタイムゾーン）
SELECT CURRENT_DATE, CURRENT_TIMESTAMP FROM DUAL;
-- 実行結果例：
-- CURRENT_DATE CURRENT_TIMESTAMP
-- ------------ ------------------------------
-- 26-3月 -26  26-3月 -26 10.30.00.000000 +09:00
-- （CURRENT_DATEは日付のみ、CURRENT_TIMESTAMPはタイムゾーン付きの日時を返す）

-- タイムゾーン変換
SELECT CURRENT_TIMESTAMP AT TIME ZONE '+00:00' AS UTC_TIME
FROM   DUAL;
-- 実行結果例：
-- UTC_TIME
-- ------------------------------
-- 26-3月 -26 01.30.00.000000 +00:00
-- （日本時間+09:00から9時間引いたUTC時刻に変換される）

-- INTERVAL の利用例
SELECT CURRENT_TIMESTAMP + INTERVAL '2' HOUR AS PLUS_2H
FROM   DUAL;
-- 実行結果例：
-- PLUS_2H
-- ------------------------------
-- 26-3月 -26 12.30.00.000000 +09:00
-- （現在時刻に2時間を加算した結果が返る）
試験のポイント： 権限は最小権限で付与し、役割単位ではロールを使います。
辞書ビュー（USER_/ALL_/DBA_）は参照範囲が異なります。
CURRENT_TIMESTAMP はタイムゾーンを保持し、AT TIME ZONE で変換できます。
