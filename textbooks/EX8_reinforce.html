データの絞り込みとソート
元ドメイン: D2 ／ 優先度: 維持

D2データの絞り込みとソート維持

模試で落とした典型ミス

  • VERIFY コマンドの機能を「置換変数の値を作成」と誤認。正：置換変数使用時に変更前／変更後の値を表示する（SQL*Plus 専用）。
  • AND と OR の優先順位：AND が先に評価される。括弧で優先順位を明示する。
  • ROWNUM と ORDER BY の組合せ：WHERE ROWNUM <= 3 ORDER BY ...は登録順の先頭3件を取って後ソート。想定と違う結果になる。

必修ルール

  • LIKE：%＝0文字以上、_＝1文字。ESCAPE 指定で % や _ をリテラル扱い可。
  • BETWEEN a AND b：a <= x <= b（両端含む）。
  • IN リスト：NULL を含むと NOT IN は常に空集合になる罠。
  • ORDER BY：既定 ASC、NULL は既定で ASC なら末尾・DESC なら先頭。NULLS FIRST/LASTで明示。
  • 行制限：12c以降は OFFSET m ROWS FETCH NEXT n ROWS ONLY。ROWNUM はソート前に評価されるため、Top-N には (SELECT ... ORDER BY ...)の外側で使う。
  • 置換変数：&＝毎回プロンプト・SQL後破棄、&&＝1回入力で永続・SQL後も値保持。DEFINE/UNDEFINE で明示管理。
  • SQL*Plus コマンド：DEFINE / SET VERIFY / SET DEFINE ON は SQL*Plus 専用（SQL Developer でも一部使える）。

ミニ演習（2問）

Q1. Top-N を正しく取る書き方（安い順3件）は？
A. SELECT * FROM (SELECT ... ORDER BY price) WHERE ROWNUM <= 3;または FETCH FIRST 3 ROWS ONLY。
Q2. &varと &&varの違いは？
A. &は実行ごとに入力を求める・実行後破棄、&&は1度入力すればセッション終了まで保持。
