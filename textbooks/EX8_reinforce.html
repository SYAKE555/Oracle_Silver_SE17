置換変数と VERIFY4問

SQL*Plus 系の置換変数では & は毎回入力、&& は再利用される。DEFINE 済みかどうか、VERIFY の役割も含めて読む必要がある。

第1回 模擬試験 / 問12 / 正答 A.C / 自己回答 B.C
問題文
VERIFYコマンドについて正しい記述はどれでしょうか。(2つ選択)
(1)		A.　置換変数の値を表示します。
(2)		B.　置換変数の値を作成します。
(3)		C.　SQL DeveloperおよびSQL*Plusで使用できます。
(4)		D.　SQL Developerでのみ使用できます。
(5)		E.　SQL*Plusでのみ使用できます。
なぜそうなるか

この問題の論点は「置換変数と VERIFY」です。SQL*Plus 系の置換変数では & は毎回入力、&& は再利用される。DEFINE 済みかどうか、VERIFY の役割も含めて読む必要がある。 したがって正答は A「置換変数の値を表示します。」 / C「SQL DeveloperおよびSQL*Plusで使用できます。」 になります。

今回の誤り

自己回答は B「置換変数の値を作成します。」 / C「SQL DeveloperおよびSQL*Plusで使用できます。」 でした。一部は当たっていますが、B「置換変数の値を作成します。」 に引っ張られて取りこぼしています。DEFINE の有無を見ずにプロンプト発生を判断したり、VERIFY を変数定義と混同しやすい。

叩き直しポイント
  • & は都度入力、&& は定義保持と覚える。
  • DEFINE 済みならプロンプトが出ない可能性を確認する。
  • VERIFY は置換前後の表示であり、変数作成ではない。

ORDER BY・ROWNUM・FETCH3問

ROWNUM は ORDER BY より前に振られるため、並べ替えてから上位 n 件を取りたいなら副問合せや FETCH FIRST を使う。ORDER BY の列別名や位置番号も正しく使う必要がある。

第2回 模擬試験 / 問24 / 正答 B / 自己回答 C
問題文
ITEM_TYPE=FOODの商品を";"区切りで1行に表示するためのSQLはどれでしょうか。
なお、ソートは製造年月日（MADE_DATE）の順とします。
(1)		A.　SELECT LISTAGG(ITEM_NAME) WITHIN GROUP (ORDER BY MADE_DATE) "FoodList" FROM ITEM WHERE ITEM_TYPE = 'FOOD';
(2)		B.　SELECT LISTAGG(ITEM_NAME, '; ') WITHIN GROUP (ORDER BY MADE_DATE) "FoodList" FROM ITEM WHERE ITEM_TYPE = 'FOOD';
(3)		C.　SELECT LISTAGG(ITEM_NAME, '; ') "FoodList" FROM ITEM WHERE ITEM_TYPE = 'FOOD'; WITHIN GROUP (ORDER BY MADE_DATE);
(4)		D.　SELECT LISTAGG(ITEM_NAME) WITHIN GROUP ORDER BY (MADE_DATE) "FoodList" FROM ITEM WHERE ITEM_TYPE = 'FOOD';
なぜそうなるか

この問題の論点は「ORDER BY・ROWNUM・FETCH」です。ROWNUM は ORDER BY より前に振られるため、並べ替えてから上位 n 件を取りたいなら副問合せや FETCH FIRST を使う。ORDER BY の列別名や位置番号も正しく使う必要がある。 したがって正答は B「SELECT LISTAGG(ITEM_NAME, '; ') WITHIN GROUP (ORDER BY …」 になります。

今回の誤り

自己回答は C「SELECT LISTAGG(ITEM_NAME, '; ') "FoodList" FROM ITEM WH…」 でした。ROWNUM と ORDER BY の評価順を逆に読んだり、FETCH/ORDER BY の構文順を崩しやすい。 正答との差は、条件の向き、句の置き場所、またはオブジェクトの性質を正確に読み切れていない点にあります。

叩き直しポイント
  • 先に並べ替えたいなら副問合せか FETCH FIRST を使う。
  • ORDER BY の位置番号は SELECT 列順に対応する。
  • FETCH / OFFSET は ORDER BY の後に続ける。

NULL 判定と WHERE 条件2問

NULL 判定は = NULL ではなく IS NULL / IS NOT NULL を使う。複数列の NULL 条件は列ごとに明示する必要がある。

第1回 模擬試験 / 問8 / 正答 D / 自己回答 C
問題文
次の条件に合ったSQLを作成する必要があります。

1. ITEM_NAMEと消費税（10%積算）を含めた価格を表示します。
2. ITEM_PRICEがNULLではない商品が対象です。
3. ITEM_NAMEがNULLの商品は対象外です。

上記の条件に合ったSQLはどれでしょうか。
　
拡大する
(1)		A.　SELECT ITEM_NAME, ITEM_PRICE * 1.10 FROM ITEM WHERE ITEM_NAME AND ITEM_PRICE IS NOT NULL;
(2)		B.　SELECT ITEM_NAME, ITEM_PRICE * 1.10 FROM ITEM WHERE ITEM_NAME IS NOT NULL AND ITEM_TYPE IS NOT NULL;
(3)		C.　SELECT ITEM_NAME, ITEM_PRICE * 1.10 FROM ITEM WHERE ITEM_NAME, ITEM_PRICE IS NOT NULL;
(4)		D.　SELECT ITEM_NAME, ITEM_PRICE * 1.10 FROM ITEM WHERE ITEM_NAME IS NOT NULL AND ITEM_PRICE IS NOT NULL;
なぜそうなるか

この問題の論点は「NULL 判定と WHERE 条件」です。NULL 判定は = NULL ではなく IS NULL / IS NOT NULL を使う。複数列の NULL 条件は列ごとに明示する必要がある。 したがって正答は D「SELECT ITEM_NAME, ITEM_PRICE * 1.10 FROM ITEM WHERE ITE…」 になります。

今回の誤り

自己回答は C「SELECT ITEM_NAME, ITEM_PRICE * 1.10 FROM ITEM WHERE ITE…」 でした。NULL を通常の値のように比較したり、複数列をまとめて IS NOT NULL にできると誤認しやすい。 正答との差は、条件の向き、句の置き場所、またはオブジェクトの性質を正確に読み切れていない点にあります。

叩き直しポイント
  • NULL 比較は必ず IS NULL / IS NOT NULL。
  • 複数列条件は AND で列ごとに書く。
  • COUNT や算術演算で NULL がどう扱われるかも合わせて確認する。

演算子優先順位1問

AND は OR より先、算術演算は比較より先など、優先順位を知らないと WHERE 条件の意味が変わる。必要なら括弧で明示する。

第1回 模擬試験 / 問26 / 正答 C.E / 自己回答 B.C
問題文
非等価結合のパフォーマンスについて正しい記述はどれでしょうか。（2つ選択）
(1)		A.　BETWEEN条件は、等号・不等号条件よりもパフォーマンスが低下します。
(2)		B.　BETWEEN条件は、等号・不等号条件よりもパフォーマンスが優れています。
(3)		C.　ANSI結合構文とOracle結合構文では、パフォーマンスに違いはありません。
(4)		D.　ANSI結合構文よりもOracle結合構文の方がパフォーマンスは優れています。
(5)		E.　表に別名をつけて列を表別名で修飾すると、パフォーマンスが向上します。
なぜそうなるか

この問題の論点は「演算子優先順位」です。AND は OR より先、算術演算は比較より先など、優先順位を知らないと WHERE 条件の意味が変わる。必要なら括弧で明示する。 したがって正答は C「ANSI結合構文とOracle結合構文では、パフォーマンスに違いはありません。」 / E「表に別名をつけて列を表別名で修飾すると、パフォーマンスが向上します。」 になります。

今回の誤り

自己回答は B「BETWEEN条件は、等号・不等号条件よりもパフォーマンスが優れています。」 / C「ANSI結合構文とOracle結合構文では、パフォーマンスに違いはありません。」 でした。一部は当たっていますが、B「BETWEEN条件は、等号・不等号条件よりもパフォーマンスが優れています。」 に引っ張られて取りこぼしています。自然言語の読み順で解釈してしまい、SQL の実際の評価順とずれやすい。

叩き直しポイント
  • 迷ったら括弧で意味を固定する。
  • AND が OR より強いことをまず確認する。
  • IN、BETWEEN、LIKE は比較条件として塊で読む。
