D5複数表の結合最優先

🔥 模試で落とした典型ミス

  • 自己結合で USING 句を使えると誤認。正：表別名が必須で INNER JOIN も可 / 誤：USING が使える / 必ず OUTER JOIN
  • FULL OUTER JOIN を「デカルト積と同じ」と誤認。正：両表の全行を返し不一致側は NULL 埋め / 誤：デカルト積＝全組合せ
  • Oracle独自結合構文（(+)）と標準構文の区別。FULL OUTER は Oracle 独自構文では非サポート、ANSI 構文のみ。
  • NATURAL JOIN と USING の併用不可ルール、ON と USING の相互排他ルールを見落とす。

📌 必修ルール

  • 結合の種類と結果件数：CROSS＝デカルト積 / INNER＝一致行のみ / LEFT・RIGHT＝片側全行＋相手NULL / FULL＝両側全行＋NULL / NATURAL＝同名列で自動結合。
  • USING：両表の列名が完全一致するときのみ使用可。USING で指定した列は 表別名. を付けると構文エラー。
  • ON：任意の条件で結合可能。USING と同時使用不可。
  • NATURAL JOIN：同名列を自動で結合条件にする。ON・USING と併用不可。列が1つも一致しなければデカルト積。
  • 自己結合：同じ表を参照するため表別名が必須。INNER でも OUTER でも可、USING は列名がぶつかるので使えない。
  • Oracle独自構文：WHERE 句に (+) を付ける。FULL OUTER は (+) で表現できないので ANSI を使う。
  • NULL と結合：結合キーに NULL がある行は INNER JOIN から除外される。NULL を含めたい場合は OUTER JOIN。

🎯 ミニ演習（3問）

Q1. 自己結合で絶対に必要なものは？
A. 表別名（エイリアス）。同じ表を2回参照するため列名が衝突する。
Q2. FULL OUTER JOIN を Oracle 独自構文 (+) で書けるか？
A. 書けない。FULL は ANSI の FULL [OUTER] JOIN でのみ記述可能。
Q3. NATURAL JOIN の2表に同名列が存在しない場合の結果は？
A. デカルト積（CROSS JOIN）と同じ結果。結合条件が生成できないため。

D6サブクエリ・集合演算最優先

🔥 模試で落とした典型ミス

  • 相関サブクエリの実行順を逆に覚えた。正：外側の各行ごとに内側が実行される / 誤：内側→外側の1回実行
  • UNION の ORDER BY は最後のSELECT にしか書けないと誤認。正：ORDER BY は文末に1つのみ、列は最初のSELECTの列名 or 位置番号で指定
  • UNION ALL と UNION の違い：UNION は重複削除＋ソート / UNION ALL は重複保持・ソートなし（高速）
  • 「一度も取引のない商品」を取得するのに UNION / INTERSECT を選択。正：MINUS（差集合）
  • EXISTS と IN の挙動差、NOT IN に NULL が混ざるときの罠を見落とす。

📌 必修ルール

  • サブクエリの実行順：通常（非相関）は内→外。相関は外の各行ごとに内を再実行。
  • 単一行サブクエリ：= / < / > を使用。2行以上返ると ORA-01427。
  • 複数行サブクエリ：IN / ANY / ALL を使用。> ANY＝最小より大、> ALL＝最大より大。
  • NOT IN と NULL：サブクエリ結果に NULL が1つでもあると NOT IN は必ず空集合。EXISTS で書き換える。
  • EXISTS：真偽のみ判定、サブクエリの SELECT リストの内容は評価しない（SELECT 1 で十分）。
  • 集合演算：UNION＝和（重複削除）、UNION ALL＝和（重複保持）、INTERSECT＝積、MINUS＝差。列数と型の対応が必須。
  • 集合演算のソート：ORDER BY は最後に1回のみ。列名は最初の SELECT のもの、または位置指定（ORDER BY 1）。
  • UNION の暗黙ソート：UNION / INTERSECT / MINUS は重複排除のため内部でソートする（UNION ALL はソートなし）。

✅ 構文・語彙チェックリスト

用途使う演算子
両方の表に存在する行を取るINTERSECT
A にあって B にない行を取るA MINUS B
両方を重複込みで連結UNION ALL（高速・ソートなし）
NULL を返す可能性のあるサブクエリで除外NOT EXISTS（NOT IN は NULL で罠）
副問合せの「存在確認のみ」WHERE EXISTS (SELECT 1 FROM ...)

🎯 ミニ演習（3問）

Q1. 「一度も注文のない顧客」を取る最も自然な書き方は？
A. customer MINUS ordered_customer、または NOT EXISTS (SELECT 1 FROM orders ...)。NOT IN は NULL で罠。
Q2. SELECT a FROM t1 UNION SELECT b FROM t2 ORDER BY a; は正しいか？
A. 正しい。ORDER BY は最後の文末に1回だけ、列名は最初の SELECT のもの。
Q3. UNION ALL と UNION どちらが速いか？
A. UNION ALL。重複排除のソート処理がないため。重複を気にしない場面では必ず ALL を選ぶ。

D3単一行関数優先

🔥 模試で落とした典型ミス

  • LIKE と文字列関数の組合せ：UPPER(col) LIKE 'S%' と UPPER(col) LIKE 'T'（%なし）を混同。
  • 日付演算で「2年前」を SYSDATE - 2*365 と書く。正：ADD_MONTHS(SYSDATE, -24) または SYSDATE - INTERVAL '2' YEAR（うるう年で誤差が出る）。
  • TO_NUMBER と TO_CHAR の入出力方向を逆に覚える。TO_CHAR(数値, 書式) / TO_NUMBER(文字, 書式)
  • INSTR の開始位置に +1 をつけるか忘れて次単語を切り出せない。
  • NVL と NVL2 の引数順・戻り値を混同。

📌 必修ルール

  • NVL(a, b)：a が NULL なら b、そうでなければ a。型は a に合わせる（b が変換される）。
  • NVL2(a, b, c)：a が NULL でなければ b、NULL なら c。第2・第3引数の型を揃える必要。
  • NULLIF(a, b)：a=b のとき NULL、違えば a。a に数値リテラル、b に NULL 直書きは ORA-00932。
  • COALESCE(a, b, c, ...)：最初の非 NULL を返す。少なくとも1引数が必須、全引数で型整合が必要。
  • CASE：単純式＝CASE col WHEN 'A' THEN ...、検索式＝CASE WHEN col IS NULL THEN ...。DECODE は = 比較限定、範囲や IS NULL は検索 CASE で。
  • TO_DATE('2024-01-31','YYYY-MM-DD')：書式を明示。環境依存の NLS_DATE_FORMAT に頼らない。
  • TO_CHAR(sysdate, 'YYYY-MM-DD HH24:MI:SS')：大文字小文字・秒指定に注意。
  • MONTHS_BETWEEN / ADD_MONTHS / NEXT_DAY / LAST_DAY / EXTRACT：それぞれ戻り値の型を覚える（数値 or DATE）。
  • ROUND / TRUNC（日付対応）：第2引数で精度指定。'MM'＝月初めで丸め、'YYYY'＝年初。
  • 暗黙変換：文字→数値（WHERE 列＝'10' など）は動くが、索引が使えなくなる可能性あり、試験ではエラーになる書式ミスに注意。

✅ 構文・語彙チェックリスト

やりたいこと関数
NULL なら 0 にするNVL(col, 0)
NULL でない値だけ '有' に置換NVL2(col, '有', '無')
2つの値が同じなら NULL にNULLIF(a, b)
最初の非NULLCOALESCE(a, b, c)
n か月後ADD_MONTHS(d, n)

🎯 ミニ演習（3問）

Q1. NVL2(comm, sal+comm, sal) の意味は？
A. comm が NULL でなければ sal+comm、NULL なら sal を返す。
Q2. 今日から 2 年経過したかの判定に最適な関数は？
A. ADD_MONTHS(made_date, 24) <= SYSDATE。+ 2*365 はうるう年で誤差。
Q3. 商品名「AAA BBB CCC」から 2 単語目を取り出す式は？
A. SUBSTR(name, INSTR(name,' ')+1, INSTR(name,' ',1,2)-INSTR(name,' ')-1)。+1 を忘れると空白が先頭に残る。

D7DML・トランザクション優先

🔥 模試で落とした典型ミス

  • ROLLBACK TO SAVEPOINT がロックまで解除すると誤認。正：SAVEPOINT 以降の変更を取り消すがロック解除はしない。SAVEPOINT 自体は残る。
  • UPDATE の SET リストで AND を区切り文字に使う選択肢を選ぶ。正：カンマ区切り。
  • INSERT ALL の WHEN 句に ELSE が使えないと誤認。正：ELSE 句あり。1行を複数表に挿入可能（INSERT FIRST は最初に合致した WHEN のみ）。
  • MERGE で UPDATE 側に WHERE 句が書けないと誤認。WHEN MATCHED THEN UPDATE SET ... WHERE ... が可能。DELETE も WHERE 付で可。

📌 必修ルール

  • COMMIT / ROLLBACK：COMMIT で確定・全SAVEPOINT消去、ROLLBACK で現在のトランザクション全破棄・全SAVEPOINT消去。
  • ROLLBACK TO SAVEPOINT s1：s1 以降の変更を破棄。s1 自体は残り、それより前の SAVEPOINT も残る。行ロックは維持される。
  • DDL の暗黙コミット：CREATE / ALTER / DROP / TRUNCATE / GRANT / REVOKE は自動的に COMMIT される。ROLLBACK できない。
  • TRUNCATE vs DELETE：TRUNCATE はDDL・高速・ログ小・ROLLBACK不可・トリガ起動しない・HWM リセット / DELETE はDML・行単位・ROLLBACK可・トリガ起動・HWMそのまま。
  • INSERT ALL（無条件）：全 INTO に全行を挿入。
  • INSERT ALL（条件付）：WHEN ～ THEN INTO、ELSE が使える。条件に合うすべての INTO に挿入。
  • INSERT FIRST：最初に合致した WHEN のみ実行。以降の WHEN はスキップ。
  • MERGE：USING 側は表・ビュー・サブクエリ。ON 条件で更新/挿入を分岐。MATCHED 側で UPDATE と DELETE を同時に記述可能。
  • SELECT FOR UPDATE：行ロックを取得。COMMIT / ROLLBACK までロックが続く。

✅ 構文・語彙チェックリスト

操作COMMIT要否ROLLBACK可否トリガ
INSERT / UPDATE / DELETE / MERGE明示必要可起動
TRUNCATE TABLE自動（DDL）不可起動しない
DROP TABLE自動（DDL）不可－

🎯 ミニ演習（3問）

Q1. INSERT ALL と INSERT FIRST の違いは？
A. ALL は条件に合う全 WHEN に挿入、FIRST は最初にヒットした WHEN のみ。
Q2. UPDATE 文で複数列を同時更新するときの区切りは？
A. カンマ。SET a=1, b=2。AND は不可。
Q3. ROLLBACK TO SAVEPOINT の後、行ロックはどうなる？
A. 維持される（解除されない）。完全な ROLLBACK や COMMIT で初めて解放。

D8DDL・オブジェクト管理優先

🔥 模試で落とした典型ミス

  • DDL 一覧問題で「ROLLBACK できる」「データ追加できる（INSERT）」を DDL 機能と混同。正：DDL は構造変更・自動COMMIT・ROLLBACK不可。データ操作は DML。
  • CHECK 制約に SYSDATE を使える選択肢を選ぶ。正：CHECK 制約では SYSDATE / CURRVAL / NEXTVAL / USER など変動値は使用不可。
  • NOT NULL の定義位置：列レベルのみ。表レベルの制約として書くと構文エラー。
  • VIEW の更新可否の条件：単純 VIEW（単一表、DISTINCT・GROUP BY・集合演算なし、式・擬似列なし）のみ更新可。WITH READ ONLY 指定で明示的に読み取り専用化。
  • SEQUENCE の CURRVAL：セッションで1度 NEXTVAL を呼んだ後でないと使えない。

📌 必修ルール

  • DDL は自動COMMIT：CREATE / ALTER / DROP / TRUNCATE / RENAME。直前のDMLも確定される。
  • 制約の5種類：PRIMARY KEY / UNIQUE / NOT NULL / CHECK / FOREIGN KEY。PK は暗黙に NOT NULL + UNIQUE。UNIQUE 制約は NULL を複数許容。
  • NOT NULL は列レベルのみ。他の制約は列レベル・表レベル両方定義可能。
  • FOREIGN KEY：ON DELETE CASCADE（親削除で子も削除） / ON DELETE SET NULL（子の外部キーを NULL 化） / 指定なしなら親に子が残ると削除不可。
  • ALTER TABLE：列追加／変更／削除／改名、制約追加・削除、列デフォルト変更。既存データを壊す変更（型狭化・NOT NULL化で NULL 存在時）は失敗。
  • VIEW：CREATE [OR REPLACE] [FORCE] VIEW ... AS SELECT。WITH READ ONLY、WITH CHECK OPTION。
  • SEQUENCE：NEXTVAL 初回呼出でセッションの CURRVAL が有効に。CACHE / NOCACHE、CYCLE / NOCYCLE。
  • INDEX：UNIQUE 制約・PK 制約作成時に自動作成。明示 CREATE INDEX は B-Tree（既定）/ BITMAP。
  • SYNONYM：PUBLIC / PRIVATE。オブジェクト名を隠蔽。
  • 権限：システム権限（CREATE SESSION 等）／オブジェクト権限（SELECT / INSERT ON table）。WITH GRANT OPTION で再付与可。ロールには WITH ADMIN OPTION。
  • 辞書ビュー：USER_*（自分所有）/ ALL_*（参照可能） / DBA_*（全体）。USER_CONSTRAINTS, USER_TABLES, USER_TAB_COLUMNS, USER_VIEWS, USER_INDEXES。
  • DATE vs TIMESTAMP：DATE＝秒精度・TZなし。TIMESTAMP＝小数秒。TIMESTAMP WITH TIME ZONE／WITH LOCAL TIME ZONE。
  • INTERVAL：YEAR TO MONTH / DAY TO SECOND。日付演算に使うと精度を落とさない。

🎯 ミニ演習（3問）

Q1. 更新可能な VIEW の条件は？
A. 単一表・DISTINCT/GROUP BY/集合演算/集計関数/擬似列/式なし・WITH READ ONLY なし。
Q2. CHECK 制約で CHECK (hire_date <= SYSDATE) は定義できるか？
A. できない。CHECK は変動関数（SYSDATE, USER, 他列のシーケンス値）を使えない。
Q3. SEQUENCE の CURRVAL を使うための前提は？
A. そのセッションで少なくとも1回 NEXTVAL を発行済みであること。

D4グループ関数・集計要復習

🔥 模試で落とした典型ミス

  • HAVING と WHERE を混同。正：WHERE は行フィルタ・集計前 / HAVING は集計後・グループフィルタ。
  • SELECT に集計関数以外の列を含めたのに GROUP BY に入れ忘れて ORA-00979。
  • COUNT(*) と COUNT(col) の差：COUNT(*) は NULL も数える、COUNT(col) は col が NULL の行を除外。

📌 必修ルール

  • SELECT 列の規則：集計関数以外のすべての列は GROUP BY に列挙が必須。
  • 集計関数は NULL を無視。ただし COUNT(*) だけは NULL 行も数える。
  • HAVING はグループ関数条件、WHERE は行条件。HAVING は GROUP BY 省略時も書けるが、書けるのは集計関数条件のみ。
  • AVG(col) ≠ SUM(col)/COUNT(*) （NULL の扱いが違う）。AVG(col) は NULL を分母にも含めない。
  • ROLLUP(a,b)：(a,b)／(a)／() の小計行を追加。CUBE(a,b) は全組合せ。

✅ 構文・語彙チェックリスト

句対象集計関数使用
WHERE行不可
GROUP BY集計の単位不可（式は可）
HAVINGグループ可
ORDER BY最終結果可

🎯 ミニ演習（3問）

Q1. SELECT dept, AVG(sal) FROM emp GROUP BY dept HAVING AVG(sal) > 5000; を WHERE で書けるか？
A. 書けない。集計結果でのフィルタは HAVING のみ。
Q2. emp(10行、うち comm が NULL＝4行)、AVG(comm) の分母は？
A. 6（NULL は無視）。
Q3. GROUP BY なしで HAVING を付けると？
A. 全行を1グループとみなす。SUM(sal) > 10000 のように書ける。

D1SQLとRDBの基礎要復習

🔥 模試で落とした典型ミス

  • DUAL 表の構造を誤認。正：1列（DUMMY, VARCHAR2(1)）・1行のデータを持つ、SYS ユーザー所有。
  • 主キー・外部キー・一意キーの NULL 許容を混同。PK 不可・UK 可・FK 可。
  • SQL の分類（DML/DDL/DCL/TCL）を混同。COMMIT は TCL、GRANT は DCL、TRUNCATE は DDL。

📌 必修ルール

  • SQL分類：DML (INSERT/UPDATE/DELETE/MERGE/SELECT※) / DDL (CREATE/ALTER/DROP/TRUNCATE/RENAME) / DCL (GRANT/REVOKE) / TCL (COMMIT/ROLLBACK/SAVEPOINT)。
  • キー：主キー＝NOT NULL+UNIQUE。外部キー＝他表 PK/UK を参照、NULL 可。一意キー＝NULL 可（複数 NULL も可）。
  • DUAL 表：1行1列、関数/式の検証用。SELECT SYSDATE FROM DUAL;
  • 正規化：第1（繰返しなし）→第2（部分関数従属除去）→第3（推移従属除去）。
  • NULL：値ではなく「未知」。NULL = NULL は UNKNOWN、IS NULL/IS NOT NULL で判定。
  • SELECT 論理処理順：FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → FETCH / ROWNUM。

🎯 ミニ演習（2問）

Q1. COMMIT はどの分類？
A. TCL（トランザクション制御言語）。
Q2. 一意キーに NULL を複数入れられるか？
A. 入れられる。NULL は「値」ではないため、重複判定の対象外。

D2データの絞り込みとソート維持

🔥 模試で落とした典型ミス

  • VERIFY コマンドの機能を「置換変数の値を作成」と誤認。正：置換変数使用時に変更前／変更後の値を表示する（SQL*Plus 専用）。
  • AND と OR の優先順位：AND が先に評価される。括弧で優先順位を明示する。
  • ROWNUM と ORDER BY の組合せ：WHERE ROWNUM <= 3 ORDER BY ... は登録順の先頭3件を取って後ソート。想定と違う結果になる。

📌 必修ルール

  • LIKE：%＝0文字以上、_＝1文字。ESCAPE 指定で % や _ をリテラル扱い可。
  • BETWEEN a AND b：a <= x <= b（両端含む）。
  • IN リスト：NULL を含むと NOT IN は常に空集合になる罠。
  • ORDER BY：既定 ASC、NULL は既定で ASC なら末尾・DESC なら先頭。NULLS FIRST/LAST で明示。
  • 行制限：12c以降は OFFSET m ROWS FETCH NEXT n ROWS ONLY。ROWNUM はソート前に評価されるため、Top-N には (SELECT ... ORDER BY ...) の外側で使う。
  • 置換変数：&＝毎回プロンプト・SQL後破棄、&&＝1回入力で永続・SQL後も値保持。DEFINE/UNDEFINE で明示管理。
  • SQL*Plus コマンド：DEFINE / SET VERIFY / SET DEFINE ON は SQL*Plus 専用（SQL Developer でも一部使える）。

🎯 ミニ演習（2問）

Q1. Top-N を正しく取る書き方（安い順3件）は？
A. SELECT * FROM (SELECT ... ORDER BY price) WHERE ROWNUM <= 3; または FETCH FIRST 3 ROWS ONLY。
Q2. &var と &&var の違いは？
A. &は実行ごとに入力を求める・実行後破棄、&&は1度入力すればセッション終了まで保持。
