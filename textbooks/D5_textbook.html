D5: 複数表の結合

Oracle Database SQL (1Z0-071) 対策
複数のテーブルを結合してデータを取得する JOIN 構文を学びます。
内部結合、外部結合、自己結合など様々な結合方法を習得します。
コマンド覚え方リファレンス
コマンド/句 意味（日本語） 覚え方（語呂合わせや連想） 主な用途 実務での使用 試験での出方（頻出パターン）
INNER JOIN 内部結合：両テーブルで条件が一致する行のみ返す 「INNERは内側だけ」—ベン図の交差部分のみ 両テーブルに存在するデータを取得する場合 使う（最も一般的な結合） NULLの行が除外されること、JOINのみでも内部結合になること
LEFT OUTER JOIN 左外部結合：左テーブルの全行＋右に一致しなければNULL 「左側（LEFT）は全員参加、右はNULLで穴埋め」 左テーブルの全データを保持しつつ、右テーブルと結合 使う（親テーブル主体の検索でよく使用） 行数の計算問題、NULLが含まれるパターン
RIGHT OUTER JOIN 右外部結合：右テーブルの全行＋左に一致しなければNULL 「RIGHT は右側全員参加」—LEFT JOINのテーブル順を入れ替えた形 右テーブルの全データを保持しつつ、左テーブルと結合 条件付き（LEFT JOINで代替されることが多い） LEFT JOINとの違い、(+) 記法との対応
FULL OUTER JOIN 完全外部結合：両テーブルの全行を返す（一致なければNULL） 「FULLは両方全部」—左も右も取りこぼしなし 両テーブルの全データを比較・確認する場合 条件付き（データ移行やデータ品質チェックなどで使用） (+) 記法では表現不可であること
CROSS JOIN 交差結合（直積）：全行の組み合わせを返す 「CROSSは掛け算」—m行×n行＝m×n行の組み合わせ すべての組み合わせリストを生成する場合 使わない（意図しない使用はデータ爆発に注意） WHERE句なし旧形式との同一性、結果行数の計算
NATURAL JOIN 自然結合：同名列を自動的に等結合する 「NATURALは自然に—列名を自動マッチング」 同名の結合列が明確な場合に使用 使わない（予期しない結合が起きる危険があるため避ける） 列名の明示不要・テーブル名修飾不可であること
SELF JOIN 自己結合：同じテーブルを2回参照して結合する 「自分と自分で結合—上司と部下が同じテーブル」 階層データ（上司-部下）の取得 使う（組織階層や親子関係のデータモデルで使用） 別名（エイリアス）が必須であること
ON 結合条件を明示的に指定する句 「ONは条件のスイッチをONにする」 異なる列名での結合、複数条件での結合 使う（最も柔軟な結合条件指定） USING句・NATURAL JOINとの使い分け
USING 同名列を指定して等結合する句 「USING は指定した列名だけ使う」—ONより簡潔 両テーブルに同名の結合列がある場合 使う（列名が同じ場合はUSINGで簡潔に書ける） テーブル名修飾（e.DEPT_ID）がエラーになること

INNER JOIN
INNER JOINJOINONUSINGNATURAL JOIN等結合

INNER JOIN の基本

INNER JOIN は両方のテーブルで条件が一致する行だけを返します。

-- ON 句を使った結合
SELECT e.LAST_NAME, e.DEPARTMENT_ID, d.DEPARTMENT_NAME
FROM   EMPLOYEES e
INNER JOIN DEPARTMENTS d
ON     e.DEPARTMENT_ID = d.DEPARTMENT_ID;
-- 実行結果例：
-- LAST_NAME            DEPARTMENT_ID DEPARTMENT_NAME
-- -------------------- ------------- ---------------
-- King                            90 Executive
-- Kochhar                         90 Executive
-- De Haan                         90 Executive
-- ...（一致する行のみ、NULLのDEPARTMENT_IDを持つ社員は除外）

-- USING 句（同名の列で結合する場合）
SELECT LAST_NAME, DEPARTMENT_ID, DEPARTMENT_NAME
FROM   EMPLOYEES
JOIN   DEPARTMENTS
USING  (DEPARTMENT_ID);
-- 実行結果例：
-- LAST_NAME            DEPARTMENT_ID DEPARTMENT_NAME
-- -------------------- ------------- ---------------
-- King                            90 Executive
-- Kochhar                         90 Executive
-- ...（ON句と同じ結果、USING句では列にテーブル名を付けてはいけない）

-- NATURAL JOIN（同名列を自動で等結合）
SELECT LAST_NAME, DEPARTMENT_NAME
FROM   EMPLOYEES
NATURAL JOIN DEPARTMENTS;
-- 実行結果例：
-- LAST_NAME            DEPARTMENT_NAME
-- -------------------- ---------------
-- King                 Executive
-- Kochhar              Executive
-- ...（同名列がすべて結合条件になるため注意）

旧来の等結合（Oracle 独自）

-- WHERE 句による等結合（非 ANSI 形式）
SELECT e.LAST_NAME, d.DEPARTMENT_NAME
FROM   EMPLOYEES e, DEPARTMENTS d
WHERE  e.DEPARTMENT_ID = d.DEPARTMENT_ID;
-- 実行結果例：
-- LAST_NAME            DEPARTMENT_NAME
-- -------------------- ---------------
-- King                 Executive
-- Kochhar              Executive
-- ...（INNER JOINと同じ結果、NULLの社員は除外される）
試験のポイント： USING 句を使う場合、結合に使った列にはテーブル名（またはエイリアス）を付けてはいけません。
NATURAL JOIN は結合列を明示しないため、予期しない結合が起きる危険があります。
INNER は省略可能（JOIN のみでも内部結合になる）。
練習問題
問題 1 #OSLV-D5-001

以下のSQL文の結果として正しいものはどれか。
```sql
SELECT e.last_name, d.department_name
FROM employees e
JOIN departments d ON e.department_id = d.department_id;
```
employeesに department_id = NULL の社員が2名いるとする。

  • A. department_idがNULLの社員2名もNULLとして結果に含まれる
  • B. department_idがNULLの社員2名は結果に含まれない
  • C. エラーになる（NULLを持つ列はJOINに使えない）
  • D. NULLとNULLが一致するとみなされdepartmentsのNULL行と結合される
解答・解説を見る

正解: B. department_idがNULLの社員2名は結果に含まれない

正解は「department_idがNULLの社員2名は結果に含まれない」である。
INNER JOIN（JOINとだけ書いた場合もINNER JOIN）は結合条件に一致する行のみを返す。
NULLは何とも等しくないため（NULL = NULLはUNKNOWN）、ON e.department_id = d.department_idはNULLの場合に一致しない。
NULLの社員も含めたい場合はLEFT OUTER JOINを使う。
選択肢DはNULL同士を等しいとみなすことはないため誤り。

問題 2 #OSLV-D5-002

以下のSQL文の実行結果の行数として正しいものはどれか。
```sql
SELECT e.last_name, d.department_name
FROM employees e
LEFT OUTER JOIN departments d
ON e.department_id = d.department_id;
```
employees: 107行（うち department_id = NULL が2行）、departments: 27行

  • A. 107行（NULLの社員2名はdepartment_nameがNULLで表示）
  • B. 105行（NULLの社員は除外）
  • C. 27行（departmentsの行数に合わせる）
  • D. 134行（107 + 27）
解答・解説を見る

正解: A. 107行（NULLの社員2名はdepartment_nameがNULLで表示）

正解は「107行（NULLの社員2名はdepartment_nameがNULLで表示）」である。
LEFT OUTER JOINは左表（employees）の全行を必ず結果に含める。
右表（departments）で対応する行がない場合（NULLの社員の場合）、右表の列はNULLとして表示される。
したがって employees の全107行が返され、department_id = NULLの2名はdepartment_nameがNULLとなる。
INNER JOINなら105行、RIGHT OUTER JOINなら右表基準。

問題 3 #OSLV-D5-003

以下のSQL文（自己結合）の目的として正しいものはどれか。
```sql
SELECT e.last_name AS 社員名,
m.last_name AS 上司名
FROM employees e
JOIN employees m ON e.manager_id = m.employee_id;
```

  • A. 全社員の部下一覧を表示する
  • B. manager_idがNULLの社員のみを表示する
  • C. 社員とその上司の名前を同じテーブルから取得する
  • D. エラーになる（同じテーブルをJOINできない）
解答・解説を見る

正解: C. 社員とその上司の名前を同じテーブルから取得する

正解は「社員とその上司の名前を同じテーブルから取得する」である。
自己結合（SELF JOIN）は同一テーブルに対して別名（エイリアス）を2つ付けてJOINする手法。
ここではemployeesテーブルをe（社員側）とm（上司側）として結合し、e.manager_id = m.employee_idで社員の上司IDと上司のemployee_idを一致させる。
manager_idがNULLの社員（最上位管理者）はINNER JOINなので結果に含まれない。
LEFT JOINにすれば全社員＋上司名NULLの行が含まれる。

外部結合（OUTER JOIN）

一方のテーブルに一致する行がなくても、NULL として結果に含めます。

種類説明
LEFT OUTER JOIN左テーブルの全行を返す。
右に一致なければ NULL
RIGHT OUTER JOIN右テーブルの全行を返す。
左に一致なければ NULL
FULL OUTER JOIN両テーブルの全行を返す。
一致なければ NULL
-- 部署なし従業員も含めて表示（LEFT OUTER JOIN）
SELECT e.LAST_NAME, d.DEPARTMENT_NAME
FROM   EMPLOYEES e
LEFT OUTER JOIN DEPARTMENTS d
ON     e.DEPARTMENT_ID = d.DEPARTMENT_ID;
-- 実行結果例：
-- LAST_NAME            DEPARTMENT_NAME
-- -------------------- ---------------
-- King                 Executive
-- Grant                （NULL）← 部署なしの社員もNULLで表示される
-- ...（全107行、部署なし社員のDEPARTMENT_NAMEはNULL）

-- 従業員のいない部署も含めて表示（RIGHT OUTER JOIN）
SELECT e.LAST_NAME, d.DEPARTMENT_NAME
FROM   EMPLOYEES e
RIGHT OUTER JOIN DEPARTMENTS d
ON     e.DEPARTMENT_ID = d.DEPARTMENT_ID;
-- 実行結果例：
-- LAST_NAME            DEPARTMENT_NAME
-- -------------------- ---------------
-- King                 Executive
-- （NULL）             Treasury ← 従業員のいない部署はLAST_NAMEがNULL
-- ...（従業員のいない部署も含む全行）

-- Oracle 独自の外部結合記法（(+) 記号）
SELECT e.LAST_NAME, d.DEPARTMENT_NAME
FROM   EMPLOYEES e, DEPARTMENTS d
WHERE  e.DEPARTMENT_ID = d.DEPARTMENT_ID(+);
-- 実行結果例：
-- LAST_NAME            DEPARTMENT_NAME
-- -------------------- ---------------
-- King                 Executive
-- Grant                （NULL）
-- ...（LEFT OUTER JOINと同じ結果。(+)はNULL補完側に付ける）
試験のポイント： Oracle 独自の (+) 記法では、NULL を補完したい側（右テーブル相当）に (+) を付けます。
FULL OUTER JOIN は (+) 記法では表現できません。
OUTER は省略可能（LEFT JOIN でも外部結合になる）。

自己結合とクロス結合
自己結合SELF JOINCROSS JOINクロス結合エイリアス

自己結合（SELF JOIN）

同じテーブルを異なるエイリアスで2回参照して結合します。
階層データ（上司-部下など）の取得に使います。

-- 従業員とその上司の名前を表示
SELECT e.LAST_NAME AS 従業員,
       m.LAST_NAME AS 上司
FROM   EMPLOYEES e
LEFT JOIN EMPLOYEES m
ON     e.MANAGER_ID = m.EMPLOYEE_ID;
-- 実行結果例：
-- 従業員                上司
-- -------------------- --------------------
-- Kochhar              King
-- De Haan              King
-- King                 （NULL）← 最上位のため上司なし
-- ...（LEFT JOINなので上司のいない社員もNULLで表示）

クロス結合（CROSS JOIN）

CROSS JOIN は全行の組み合わせを返します（直積）。
結果行数 = テーブル1の行数 x テーブル2の行数。

-- CROSS JOIN（ANSI 形式）
SELECT e.LAST_NAME, d.DEPARTMENT_NAME
FROM   EMPLOYEES e
CROSS JOIN DEPARTMENTS d;
-- 実行結果例：
-- LAST_NAME            DEPARTMENT_NAME
-- -------------------- ---------------
-- King                 Administration
-- King                 Marketing
-- King                 Purchasing
-- ...（107行 × 27行 = 2,889行のすべての組み合わせが返される）

-- 旧来の表記（WHERE 句なし）
SELECT e.LAST_NAME, d.DEPARTMENT_NAME
FROM   EMPLOYEES e, DEPARTMENTS d;
-- 実行結果例：
-- LAST_NAME            DEPARTMENT_NAME
-- -------------------- ---------------
-- King                 Administration
-- King                 Marketing
-- ...（CROSS JOINと同じ結果。WHERE句の書き忘れによる意図しない直積に注意）
試験のポイント： 自己結合では必ずテーブルエイリアスが必要です。
クロス結合は意図せず WHERE を省略した場合にも発生するため注意が必要です。
上司が存在しない場合（社長など）は MANAGER_ID が NULL になるため、INNER JOIN ではなく LEFT JOIN を使うと全員が表示されます。
