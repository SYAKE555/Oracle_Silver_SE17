TO_CHAR・TO_NUMBER・TO_DATE の書式変換6問

文字列として保持された数値や日付を演算するには、まず TO_NUMBER や TO_DATE で型変換し、その後に TO_CHAR で表示形式を整える。書式モデルが一致しなければ失敗する。

論点の定義

型変換関数は、内部計算のために元の型へ戻す処理と、表示形式へ整える処理を分けて書く。数値演算の前に TO_NUMBER、日付演算の前に TO_DATE、表示の直前に TO_CHAR を使う。

句の並び順（Oracle 正式構文）
SELECT 単一行関数(列) -- 値の変換・整形（列ごとに結果） FROM 表 WHERE 単一行関数(列) 比較演算子 値 ORDER BY 単一行関数(列); -- 単一行関数は SELECT / WHERE / ORDER BY のどれにも書ける（GROUP BY 後の HAVING 内でも可）。 -- 変換順序: 演算前に TO_NUMBER / TO_DATE、表示直前に TO_CHAR。 -- NULL 処理: NVL(式, 代替) / NVL2(式, 非NULL, NULL) / COALESCE / CASE。
この論点の基本形
SELECT TO_CHAR(
         TO_NUMBER(shohin_kakaku, '999,999.99') * 0.30,
         '999,999.00'
       ) AS discount_price
FROM   shohin;
成立条件
  • 文字列として保存された数値へ直接乗算や加算を行う前に、TO_NUMBER で数値へ変換する。
  • 表示形式を指定する最終段階では TO_CHAR を使い、TO_NUMBER を外側に置かない。
  • 書式モデルは元データまたは出力形式と桁数・小数点位置が一致していなければならない。
判定手順
  1. まず元データの型が文字列か数値か日付かを確認する。
  2. 次に演算前の型変換と表示直前の書式変換を分離して読む。
  3. 最後に書式モデルが入力側・出力側のどちらへ掛かっているかを確認する。
失点しやすい点: 変換の向きを逆にしたり、表示書式と内部型の処理順を取り違えやすい。

SUBSTR・INSTR・TRIM・REPLACE の使い分け5問

文字列の一部抽出では、位置取得に INSTR、切り出しに SUBSTR、不要部分の削除に TRIM、置換に REPLACE を使い分ける。空白位置の +1 を忘れると全体がずれる。

論点の定義

文字列関数は 1 行ずつ入力を受け取り、変換後の文字列または位置情報を返す。大文字小文字の正規化、部分抽出、位置探索は役割を分けて扱う。

句の並び順（Oracle 正式構文）
SELECT 単一行関数(列) -- 値の変換・整形（列ごとに結果） FROM 表 WHERE 単一行関数(列) 比較演算子 値 ORDER BY 単一行関数(列); -- 単一行関数は SELECT / WHERE / ORDER BY のどれにも書ける（GROUP BY 後の HAVING 内でも可）。 -- 変換順序: 演算前に TO_NUMBER / TO_DATE、表示直前に TO_CHAR。 -- NULL 処理: NVL(式, 代替) / NVL2(式, 非NULL, NULL) / COALESCE / CASE。
この論点の基本形
SELECT UPPER(item_name),
       SUBSTR(item_name, 1, 3),
       INSTR(item_name, ' ') 
FROM   item
WHERE  UPPER(item_name) LIKE 'S%';
成立条件
  • LIKE のワイルドカードは % が 0 文字以上、_ が 1 文字である。
  • INSTR は位置、SUBSTR は切り出し、TRIM は前後除去、REPLACE は置換に使う。
  • UPPER や LOWER を使うなら比較側の文字列も同じ規則でそろえる。
判定手順
  1. まず要求が前方一致・部分一致・文字抽出のどれかを判定する。
  2. 次に正規化関数を列側と比較値側の両方へ必要か確認する。
  3. 位置を使う処理なら INSTR、切り出しなら SUBSTR と機能を分ける。
失点しやすい点: 位置の起点や切り出し長を誤り、ほぼ正しそうな SQL を選んでしまいやすい。

DATE 型の差は日数で返る。月単位なら MONTHS_BETWEEN、月加算なら ADD_MONTHS を使う。年数を 365 日換算で書くと境界条件を外しやすい。

論点の定義

DATE 型の減算結果は日数であり、月単位の計算には MONTHS_BETWEEN や ADD_MONTHS を用いる。表示形式の整形は TO_CHAR、演算前の型変換は TO_DATE や TO_NUMBER が担当する。

句の並び順（Oracle 正式構文）
SELECT 単一行関数(列) -- 値の変換・整形（列ごとに結果） FROM 表 WHERE 単一行関数(列) 比較演算子 値 ORDER BY 単一行関数(列); -- 単一行関数は SELECT / WHERE / ORDER BY のどれにも書ける（GROUP BY 後の HAVING 内でも可）。 -- 変換順序: 演算前に TO_NUMBER / TO_DATE、表示直前に TO_CHAR。 -- NULL 処理: NVL(式, 代替) / NVL2(式, 非NULL, NULL) / COALESCE / CASE。
この論点の基本形
SELECT ADD_MONTHS(made_date, 24) AS two_years_later,
       MONTHS_BETWEEN(SYSDATE, made_date) AS elapsed_months,
       TO_CHAR(made_date, 'YYYY-MM-DD') AS made_ymd
FROM   item;

NULL 関数と条件式2問

NVL、NVL2、NULLIF、COALESCE、CASE、DECODE は、NULL や条件分岐を表すための関数群であり、引数順と戻り値の型整合が重要である。

論点の定義

単一行関数は各行に対して 1 つの結果を返し、文字列・数値・日付・NULL・条件分岐の各カテゴリで役割が分かれる。

句の並び順（Oracle 正式構文）
SELECT 単一行関数(列) -- 値の変換・整形（列ごとに結果） FROM 表 WHERE 単一行関数(列) 比較演算子 値 ORDER BY 単一行関数(列); -- 単一行関数は SELECT / WHERE / ORDER BY のどれにも書ける（GROUP BY 後の HAVING 内でも可）。 -- 変換順序: 演算前に TO_NUMBER / TO_DATE、表示直前に TO_CHAR。 -- NULL 処理: NVL(式, 代替) / NVL2(式, 非NULL, NULL) / COALESCE / CASE。
この論点の基本形
SELECT ROUND(price, 2),
       NVL(discount, 0),
       CASE WHEN quantity IS NULL THEN 0 ELSE quantity END
FROM   item;
成立条件
  • ROUND は四捨五入、TRUNC は切り捨てであり、結果が変わる境界値を意識する。
  • NVL と NVL2 は引数の意味が異なり、CASE は一般的な条件分岐に使える。
  • 単一行関数は SELECT 句だけでなく WHERE 句や ORDER BY でも利用できる。
判定手順
  1. 何を変換したいのかを文字列・数値・日付・NULL 処理に分ける。
  2. 入力型と戻り値型が式全体で整合しているか確認する。
  3. 境界値が変わる関数では、丸め・切り捨て・NULL 代替の効果を具体的に追う。
失点しやすい点: NVL と NVL2 の引数順、CASE と DECODE の使い分け、NULLIF の意味を混同しやすい。
