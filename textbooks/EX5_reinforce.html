シーケンス・シノニム・索引11問

シーケンスは連番供給、シノニムは別名、索引は検索高速化のためのオブジェクトである。INVISIBLE INDEX、NEXTVAL/CURRVAL、PUBLIC SYNONYM など固有ルールが問われる。

論点の定義

Oracle のオブジェクト管理問題では、ビュー、索引、シーケンス、シノニム、権限、日時型のそれぞれに固有の成立条件がある。

句の並び順（Oracle 正式構文）
CREATE TABLE 表 ( 列 型 [DEFAULT 値] [NOT NULL] [CONSTRAINT 名 PRIMARY KEY | …] ); ALTER TABLE 表 ADD (列 型 [DEFAULT …] [NOT NULL]); -- 既存行ありでNOT NULLなら DEFAULT 必須 ALTER TABLE 表 MODIFY (列 型 | DEFAULT | NOT NULL); ALTER TABLE 表 DROP COLUMN 列; CREATE VIEW v AS SELECT …; -- 定義保持。基表複製ではない CREATE SEQUENCE s START WITH 1 INCREMENT BY 1; -- CURRVAL は NEXTVAL 実行後のみ有効 CREATE INDEX idx ON 表(列); GRANT 権限 ON 表 TO ユーザ [WITH GRANT OPTION]; -- DDL はすべて暗黙 COMMIT を伴う。DEFAULT は値省略時 / VALUES(DEFAULT) で補完。
この論点の基本形
CREATE VIEW v_item AS
SELECT item_id, item_name FROM item;

CREATE SEQUENCE seq_item START WITH 1;
GRANT SELECT ON item TO user_name;
成立条件
  • ビューは定義を保持するオブジェクトであり、基表そのものを複製するわけではない。
  • シーケンスの CURRVAL は同一セッションで NEXTVAL 実行後にのみ参照できる。
  • オブジェクト権限とシステム権限では付与オプションが異なる。
判定手順
  1. 何のオブジェクトを操作している文かを最初に確定する。
  2. そのオブジェクト固有の使用条件や制約を確認する。
  3. 権限・時刻・索引のような副作用の有無を最後に判定する。
失点しやすい点: CURRVAL の利用条件、INVISIBLE INDEX の更新有無、シノニムの対象範囲を曖昧にしやすい。

論点の定義

Oracle のオブジェクト管理問題では、ビュー、索引、シーケンス、シノニム、権限、日時型のそれぞれに固有の成立条件がある。

句の並び順（Oracle 正式構文）
CREATE TABLE 表 ( 列 型 [DEFAULT 値] [NOT NULL] [CONSTRAINT 名 PRIMARY KEY | …] ); ALTER TABLE 表 ADD (列 型 [DEFAULT …] [NOT NULL]); -- 既存行ありでNOT NULLなら DEFAULT 必須 ALTER TABLE 表 MODIFY (列 型 | DEFAULT | NOT NULL); ALTER TABLE 表 DROP COLUMN 列; CREATE VIEW v AS SELECT …; -- 定義保持。基表複製ではない CREATE SEQUENCE s START WITH 1 INCREMENT BY 1; -- CURRVAL は NEXTVAL 実行後のみ有効 CREATE INDEX idx ON 表(列); GRANT 権限 ON 表 TO ユーザ [WITH GRANT OPTION]; -- DDL はすべて暗黙 COMMIT を伴う。DEFAULT は値省略時 / VALUES(DEFAULT) で補完。

  • オブジェクト権限とシステム権限では付与オプションが異なる。

  2. そのオブジェクト固有の使用条件や制約を確認する。

制約定義と有効化・無効化7問

主キー、外部キー、CHECK、NOT NULL などの制約は、型や参照整合性を守るための定義である。ENABLE/DISABLE、CASCADE、SYSDATE 使用可否など細部の制約規則が問われる。

論点の定義

DDL は表定義や制約を変更する文であり、列定義・制約定義・既存データへの影響を同時に読む必要がある。DEFAULT は値省略時に補完されるが、列指定や VALUES 個数との対応は別に守られる。

句の並び順（Oracle 正式構文）
CREATE TABLE 表 ( 列 型 [DEFAULT 値] [NOT NULL] [CONSTRAINT 名 PRIMARY KEY | …] ); ALTER TABLE 表 ADD (列 型 [DEFAULT …] [NOT NULL]); -- 既存行ありでNOT NULLなら DEFAULT 必須 ALTER TABLE 表 MODIFY (列 型 | DEFAULT | NOT NULL); ALTER TABLE 表 DROP COLUMN 列; CREATE VIEW v AS SELECT …; -- 定義保持。基表複製ではない CREATE SEQUENCE s START WITH 1 INCREMENT BY 1; -- CURRVAL は NEXTVAL 実行後のみ有効 CREATE INDEX idx ON 表(列); GRANT 権限 ON 表 TO ユーザ [WITH GRANT OPTION]; -- DDL はすべて暗黙 COMMIT を伴う。DEFAULT は値省略時 / VALUES(DEFAULT) で補完。
この論点の基本形
ALTER TABLE item
ADD status VARCHAR2(10) DEFAULT 'NEW' NOT NULL;

INSERT INTO item (item_id, item_name)
VALUES ('1001', 'ITEM1');

DEFAULT と列追加・挿入5問

DEFAULT は値を省略したときに補われる。既存行がある表へ NOT NULL 列を追加するなら、DEFAULT と NOT NULL をセットで与えないと既存行を満たせない。

論点の定義

DDL は表定義や制約を変更する文であり、列定義・制約定義・既存データへの影響を同時に読む必要がある。DEFAULT は値省略時に補完されるが、列指定や VALUES 個数との対応は別に守られる。

句の並び順（Oracle 正式構文）
CREATE TABLE 表 ( 列 型 [DEFAULT 値] [NOT NULL] [CONSTRAINT 名 PRIMARY KEY | …] ); ALTER TABLE 表 ADD (列 型 [DEFAULT …] [NOT NULL]); -- 既存行ありでNOT NULLなら DEFAULT 必須 ALTER TABLE 表 MODIFY (列 型 | DEFAULT | NOT NULL); ALTER TABLE 表 DROP COLUMN 列; CREATE VIEW v AS SELECT …; -- 定義保持。基表複製ではない CREATE SEQUENCE s START WITH 1 INCREMENT BY 1; -- CURRVAL は NEXTVAL 実行後のみ有効 CREATE INDEX idx ON 表(列); GRANT 権限 ON 表 TO ユーザ [WITH GRANT OPTION]; -- DDL はすべて暗黙 COMMIT を伴う。DEFAULT は値省略時 / VALUES(DEFAULT) で補完。
この論点の基本形
ALTER TABLE item
ADD status VARCHAR2(10) DEFAULT 'NEW' NOT NULL;

INSERT INTO item (item_id, item_name)
VALUES ('1001', 'ITEM1');
成立条件
  • 既存行がある表へ NOT NULL 列を追加する場合、DEFAULT を伴わないと成立しない。
  • INSERT 文で DEFAULT を使うなら、列リストと VALUES の対応を厳密に守る。
  • DDL は暗黙 COMMIT を伴うため、DML や TCL と切り分けて理解する。
判定手順
  1. 対象が表定義変更かデータ操作かを最初に分類する。
  2. 次に既存行の有無、NULL 許容、DEFAULT 補完の関係を確認する。
  3. 最後に列数・列順・制約条件が SQL 文法どおりかを確認する。

DDL と DML/TCL の切り分け4問

CREATE、ALTER、DROP、TRUNCATE などは DDL、INSERT/UPDATE/DELETE/MERGE は DML、COMMIT/ROLLBACK/SAVEPOINT は TCL である。DDL は暗黙コミットを伴う。

論点の定義

DDL は表定義や制約を変更する文であり、列定義・制約定義・既存データへの影響を同時に読む必要がある。DEFAULT は値省略時に補完されるが、列指定や VALUES 個数との対応は別に守られる。

句の並び順（Oracle 正式構文）
CREATE TABLE 表 ( 列 型 [DEFAULT 値] [NOT NULL] [CONSTRAINT 名 PRIMARY KEY | …] ); ALTER TABLE 表 ADD (列 型 [DEFAULT …] [NOT NULL]); -- 既存行ありでNOT NULLなら DEFAULT 必須 ALTER TABLE 表 MODIFY (列 型 | DEFAULT | NOT NULL); ALTER TABLE 表 DROP COLUMN 列; CREATE VIEW v AS SELECT …; -- 定義保持。基表複製ではない CREATE SEQUENCE s START WITH 1 INCREMENT BY 1; -- CURRVAL は NEXTVAL 実行後のみ有効 CREATE INDEX idx ON 表(列); GRANT 権限 ON 表 TO ユーザ [WITH GRANT OPTION]; -- DDL はすべて暗黙 COMMIT を伴う。DEFAULT は値省略時 / VALUES(DEFAULT) で補完。
この論点の基本形
ALTER TABLE item
ADD status VARCHAR2(10) DEFAULT 'NEW' NOT NULL;

INSERT INTO item (item_id, item_name)
VALUES ('1001', 'ITEM1');
成立条件
  • 既存行がある表へ NOT NULL 列を追加する場合、DEFAULT を伴わないと成立しない。
  • INSERT 文で DEFAULT を使うなら、列リストと VALUES の対応を厳密に守る。
  • DDL は暗黙 COMMIT を伴うため、DML や TCL と切り分けて理解する。
判定手順
  1. 対象が表定義変更かデータ操作かを最初に分類する。
  2. 次に既存行の有無、NULL 許容、DEFAULT 補完の関係を確認する。
  3. 最後に列数・列順・制約条件が SQL 文法どおりかを確認する。

MERGE は 1 つの対象表に対し、ON 条件で一致時は UPDATE、非一致時は INSERT を行う。USING には表、ビュー、サブクエリを使える。

論点の定義

MERGE は一致時 UPDATE、非一致時 INSERT を 1 文で行う DML である。更新対象は 1 表だけで、USING には比較元の表や副問合せを置く。

句の並び順（Oracle 正式構文）
CREATE TABLE 表 ( 列 型 [DEFAULT 値] [NOT NULL] [CONSTRAINT 名 PRIMARY KEY | …] ); ALTER TABLE 表 ADD (列 型 [DEFAULT …] [NOT NULL]); -- 既存行ありでNOT NULLなら DEFAULT 必須 ALTER TABLE 表 MODIFY (列 型 | DEFAULT | NOT NULL); ALTER TABLE 表 DROP COLUMN 列; CREATE VIEW v AS SELECT …; -- 定義保持。基表複製ではない CREATE SEQUENCE s START WITH 1 INCREMENT BY 1; -- CURRVAL は NEXTVAL 実行後のみ有効 CREATE INDEX idx ON 表(列); GRANT 権限 ON 表 TO ユーザ [WITH GRANT OPTION]; -- DDL はすべて暗黙 COMMIT を伴う。DEFAULT は値省略時 / VALUES(DEFAULT) で補完。
この論点の基本形
MERGE INTO target t
USING source s
ON (t.id = s.id)
WHEN MATCHED THEN
  UPDATE SET t.name = s.name
WHEN NOT MATCHED THEN
  INSERT (id, name) VALUES (s.id, s.name);
成立条件
  • MATCHED 側は UPDATE、NOT MATCHED 側は INSERT が基本形である。
  • 比較条件は ON 句で指定し、更新対象表は MERGE INTO 側に 1 つだけ書く。
  • USING には表、ビュー、副問合せを置ける。
判定手順
  1. 対象表と比較元の役割を切り分ける。
  2. ON 句で一致条件を読んだ後、MATCHED/NOT MATCHED の処理内容を確認する。
  3. 複数表更新のように見える選択肢は MERGE の文法外として除外する。
失点しやすい点: WHEN MATCHED で INSERT、WHEN NOT MATCHED で UPDATE のように逆向きに書いてしまいがちで、複数表更新もできると誤認しやすい。
