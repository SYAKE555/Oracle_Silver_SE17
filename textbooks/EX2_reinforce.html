サブクエリ・集合演算
元ドメイン: D6 ／ 優先度: 最優先

D6サブクエリ・集合演算最優先

🔥 模試で落とした典型ミス

  • 相関サブクエリの実行順を逆に覚えた。正：外側の各行ごとに内側が実行される / 誤：内側→外側の1回実行
  • UNION の ORDER BY は最後のSELECT にしか書けないと誤認。正：ORDER BY は文末に1つのみ、列は最初のSELECTの列名 or 位置番号で指定
  • UNION ALL と UNION の違い：UNION は重複削除＋ソート / UNION ALL は重複保持・ソートなし（高速）
  • 「一度も取引のない商品」を取得するのに UNION / INTERSECT を選択。正：MINUS（差集合）
  • EXISTS と IN の挙動差、NOT IN に NULL が混ざるときの罠を見落とす。

📌 必修ルール

  • サブクエリの実行順：通常（非相関）は内→外。相関は外の各行ごとに内を再実行。
  • 単一行サブクエリ：= / < / > を使用。2行以上返ると ORA-01427。
  • 複数行サブクエリ：IN / ANY / ALL を使用。> ANY＝最小より大、> ALL＝最大より大。
  • NOT IN と NULL：サブクエリ結果に NULL が1つでもあると NOT IN は必ず空集合。EXISTS で書き換える。
  • EXISTS：真偽のみ判定、サブクエリの SELECT リストの内容は評価しない（SELECT 1 で十分）。
  • 集合演算：UNION＝和（重複削除）、UNION ALL＝和（重複保持）、INTERSECT＝積、MINUS＝差。列数と型の対応が必須。
  • 集合演算のソート：ORDER BY は最後に1回のみ。列名は最初の SELECT のもの、または位置指定（ORDER BY 1）。
  • UNION の暗黙ソート：UNION / INTERSECT / MINUS は重複排除のため内部でソートする（UNION ALL はソートなし）。

✅ 構文・語彙チェックリスト

用途使う演算子
両方の表に存在する行を取るINTERSECT
A にあって B にない行を取るA MINUS B
両方を重複込みで連結UNION ALL（高速・ソートなし）
NULL を返す可能性のあるサブクエリで除外NOT EXISTS（NOT IN は NULL で罠）
副問合せの「存在確認のみ」WHERE EXISTS (SELECT 1 FROM ...)

🎯 ミニ演習（3問）

Q1. 「一度も注文のない顧客」を取る最も自然な書き方は？
A. customer MINUS ordered_customer、または NOT EXISTS (SELECT 1 FROM orders ...)。NOT IN は NULL で罠。
Q2. SELECT a FROM t1 UNION SELECT b FROM t2 ORDER BY a; は正しいか？
A. 正しい。ORDER BY は最後の文末に1回だけ、列名は最初の SELECT のもの。
Q3. UNION ALL と UNION どちらが速いか？
A. UNION ALL。重複排除のソート処理がないため。重複を気にしない場面では必ず ALL を選ぶ。
