COMMIT・ROLLBACK・SAVEPOINT6問

COMMIT は変更確定とロック解放、ROLLBACK TO SAVEPOINT は指定地点以降の変更だけを戻す。
SAVEPOINT 自体や以前の SAVEPOINT は残るが、COMMIT 後は全て消える。

論点の定義

トランザクションは COMMIT または ROLLBACK で区切られる 1 まとまりの処理である。
DML は未確定状態を持てるが、DDL 実行時には暗黙 COMMIT が発生する。

句の並び順（Oracle 正式構文）
INSERT INTO 表 [(列リスト)] VALUES (値リスト); -- 列数と順序を一致 UPDATE 表 SET 列 = 値 [, …] [WHERE 条件]; -- WHERE 省略で全行更新 DELETE FROM 表 [WHERE 条件]; -- DML：ロールバック可能 MERGE INTO 対象 t USING 比較元 s ON (条件) WHEN MATCHED THEN UPDATE SET … WHEN NOT MATCHED THEN INSERT (…) VALUES (…); -- TCL -- SAVEPOINT 名称; … ROLLBACK TO 名称; COMMIT; -- DDL (CREATE/ALTER/DROP/TRUNCATE) は暗黙 COMMIT。TRUNCATE はロールバック不可。 -- COMMIT でロック解放・SAVEPOINT 消去。ROLLBACK TO は指定地点以降のみ取消。
この論点の基本形
SAVEPOINT before_update;
UPDATE invoices
SET    status = 'PAID'
WHERE  invoice_id = 10;
ROLLBACK TO before_update;
COMMIT;
成立条件
  • COMMIT は変更確定とロック解放、SAVEPOINT 消去を行う。
  • ROLLBACK TO SAVEPOINT は指定地点以降の変更だけを戻す。
  • TRUNCATE や ALTER などの DDL はトランザクション境界を強制する。
判定手順
  1. まず文が DML か DDL かを分類する。
  2. 次に変更が未確定で残るか、即時確定されるかを判断する。
  3. SAVEPOINT がある場合は、どこまで戻せるかを時系列で追う。
失点しやすい点: ROLLBACK TO SAVEPOINT でロックまで解放される、COMMIT 後も SAVEPOINT が残る、と誤認しやすい。

DML 総合2問

DML 問題では、対象行の決まり方、更新タイミング、トランザクション制御を順番に読む必要がある。
1文の中で何が確定し、何が取り消せるかが核心になる。

論点の定義

トランザクションは COMMIT または ROLLBACK で区切られる 1 まとまりの処理である。
DML は未確定状態を持てるが、DDL 実行時には暗黙 COMMIT が発生する。

句の並び順（Oracle 正式構文）
INSERT INTO 表 [(列リスト)] VALUES (値リスト); -- 列数と順序を一致 UPDATE 表 SET 列 = 値 [, …] [WHERE 条件]; -- WHERE 省略で全行更新 DELETE FROM 表 [WHERE 条件]; -- DML：ロールバック可能 MERGE INTO 対象 t USING 比較元 s ON (条件) WHEN MATCHED THEN UPDATE SET … WHEN NOT MATCHED THEN INSERT (…) VALUES (…); -- TCL -- SAVEPOINT 名称; … ROLLBACK TO 名称; COMMIT; -- DDL (CREATE/ALTER/DROP/TRUNCATE) は暗黙 COMMIT。TRUNCATE はロールバック不可。 -- COMMIT でロック解放・SAVEPOINT 消去。ROLLBACK TO は指定地点以降のみ取消。
この論点の基本形
SAVEPOINT before_update;
UPDATE invoices
SET    status = 'PAID'
WHERE  invoice_id = 10;
ROLLBACK TO before_update;
COMMIT;
成立条件
  • COMMIT は変更確定とロック解放、SAVEPOINT 消去を行う。
  • ROLLBACK TO SAVEPOINT は指定地点以降の変更だけを戻す。
  • TRUNCATE や ALTER などの DDL はトランザクション境界を強制する。
判定手順
  1. まず文が DML か DDL かを分類する。
  2. 次に変更が未確定で残るか、即時確定されるかを判断する。
  3. SAVEPOINT がある場合は、どこまで戻せるかを時系列で追う。
失点しやすい点: 構文だけを見て、実行後の状態変化まで追えずに失点しやすい。

INSERT ALL / FIRST2問

INSERT ALL は条件に合う全ての INTO に挿入し、INSERT FIRST は最初に一致した INTO だけに挿入する。
ELSE 句や条件付き挿入の位置も重要である。

論点の定義

DML 文は、対象行の決定、変更内容の記述、確定/取消の可否を文法どおりに記述する必要がある。
UPDATE や INSERT ALL/FIRST、MERGE は句の位置が崩れると不成立になる。

句の並び順（Oracle 正式構文）
INSERT INTO 表 [(列リスト)] VALUES (値リスト); -- 列数と順序を一致 UPDATE 表 SET 列 = 値 [, …] [WHERE 条件]; -- WHERE 省略で全行更新 DELETE FROM 表 [WHERE 条件]; -- DML：ロールバック可能 MERGE INTO 対象 t USING 比較元 s ON (条件) WHEN MATCHED THEN UPDATE SET … WHEN NOT MATCHED THEN INSERT (…) VALUES (…); -- TCL -- SAVEPOINT 名称; … ROLLBACK TO 名称; COMMIT; -- DDL (CREATE/ALTER/DROP/TRUNCATE) は暗黙 COMMIT。TRUNCATE はロールバック不可。 -- COMMIT でロック解放・SAVEPOINT 消去。ROLLBACK TO は指定地点以降のみ取消。
この論点の基本形
UPDATE invoices i
SET    amount = (
         SELECT SUM(l.amount)
         FROM   invoice_lines l
         WHERE  l.invoice_id = i.invoice_id
       )
WHERE  i.status = 'OPEN';
成立条件
  • UPDATE の SET は 1 回だけ書き、複数列代入はカンマで並べる。
  • 相関サブクエリを使う場合は更新行ごとに副問合せが評価される。
  • INSERT ALL は一致したすべて、INSERT FIRST は最初に一致した INTO のみへ挿入する。
判定手順
  1. まず対象行を決める WHERE や ON 句を確認する。
  2. 次に SET、VALUES、WHEN 節が Oracle の文法順に並んでいるかを見る。
  3. 副問合せがある場合は単一行保証または条件分岐の位置を確認する。
失点しやすい点: ALL と FIRST の挙動差を曖昧にし、ELSE の有無や条件評価順で失点しやすい。

UPDATE とサブクエリ1問

UPDATE の SET 句で相関サブクエリを使うと、更新対象行ごとにサブクエリが評価される。
サブクエリが複数行を返せばエラーになる。

論点の定義

DML 文は、対象行の決定、変更内容の記述、確定/取消の可否を文法どおりに記述する必要がある。
UPDATE や INSERT ALL/FIRST、MERGE は句の位置が崩れると不成立になる。

句の並び順（Oracle 正式構文）
INSERT INTO 表 [(列リスト)] VALUES (値リスト); -- 列数と順序を一致 UPDATE 表 SET 列 = 値 [, …] [WHERE 条件]; -- WHERE 省略で全行更新 DELETE FROM 表 [WHERE 条件]; -- DML：ロールバック可能 MERGE INTO 対象 t USING 比較元 s ON (条件) WHEN MATCHED THEN UPDATE SET … WHEN NOT MATCHED THEN INSERT (…) VALUES (…); -- TCL -- SAVEPOINT 名称; … ROLLBACK TO 名称; COMMIT; -- DDL (CREATE/ALTER/DROP/TRUNCATE) は暗黙 COMMIT。TRUNCATE はロールバック不可。 -- COMMIT でロック解放・SAVEPOINT 消去。ROLLBACK TO は指定地点以降のみ取消。
この論点の基本形
UPDATE invoices i
SET    amount = (
         SELECT SUM(l.amount)
         FROM   invoice_lines l
         WHERE  l.invoice_id = i.invoice_id
       )
WHERE  i.status = 'OPEN';
成立条件
  • UPDATE の SET は 1 回だけ書き、複数列代入はカンマで並べる。
  • 相関サブクエリを使う場合は更新行ごとに副問合せが評価される。
  • INSERT ALL は一致したすべて、INSERT FIRST は最初に一致した INTO のみへ挿入する。
判定手順
  1. まず対象行を決める WHERE や ON 句を確認する。
  2. 次に SET、VALUES、WHEN 節が Oracle の文法順に並んでいるかを見る。
  3. 副問合せがある場合は単一行保証または条件分岐の位置を確認する。
失点しやすい点: サブクエリが先に1回だけ実行されると思い込み、相関性や複数行エラーを見落としやすい。
